# ADR-0195: A failed attempt classifies its cause

- **Status:** Proposed
- **Date:** 2026-08-14

## Context

A dispatched attempt reports one bit. `Fact::AttemptCompleted` carries `passed: bool` (`crates/aether-bloomery/src/reduce/event.rs:142`), the reducer reads it in `reduce_attempt_completed` (`crates/aether-bloomery/src/reduce/attempt.rs:192`), and a false value falls through to `retry_or_wedge` (`crates/aether-bloomery/src/reduce/attempt.rs:346`), which spends one of the stage's `retry_budget` rolls and re-dispatches the same stage with a model behind it. Every recovery the pipeline knows how to perform hangs off that bit.

Two independent questions hide inside it. Did the attempt produce an artifact, and did anything render a verdict over that artifact? They vary independently, and the correct response depends on both:

| artifact | verdict | what happened | correct response |
|---|---|---|---|
| produced | passing | the ordinary case | advance |
| produced | failing | the work is bad | refine on the artifact, with findings |
| produced | none | the machinery failed | re-run the gate over the same artifact, no model |
| absent | — | the model failed | re-run the stage |
| absent | — | the order was already satisfied | advance |

The pipeline answers the first, second, and fourth rows correctly and the third and fifth wrongly, because a single bit cannot carry the distinction those two rows turn on. A gate that never ran and a gate that ran and refused both arrive at the reducer as `passed: false`, so a machinery failure buys a repair lap against an artifact nobody has yet found fault with. A lane that correctly concludes there is nothing to do arrives the same way, so a satisfied order is refined against until its budget is gone.

The distinction is not novel here, and this is the part worth dwelling on: it already exists in the code, twice, and reaches neither of the two wrong rows.

It exists at the backend as a three-valued lane status, `enum LaneStatus { Pass, Fail, Environment }` (`crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:1465`), under a doc comment that states this decision's own thesis: "Three-valued rather than a boolean because `environment` is not a verdict on the subject at all (ADR-0176): the lane is reporting that it could not judge one, and collapsing that into `Fail` is what charged a member repair lap for a host outage." And it exists in the wire vocabulary as `StageVerdict::ExecutorFault` (`crates/aether-bloomery/src/inward.rs:46`), which "asserts nothing about the subject: not a pass, and not the failure a candidate could repair", mapping to `EvidenceKind::ExecutorFault` (`crates/aether-bloomery/src/values/mod.rs:184`) through `StageVerdict::evidence_kind` (`crates/aether-bloomery/src/inward.rs:50`).

Three narrow conditions keep that vocabulary away from the cases that need it. The fault verdict is reachable only when the lane body stamps `"status": "environment"` into its own evidence (`parse_status`, `crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:1475`), so it is self-reported by the very child whose machinery may have died; it is excluded for the construct lane and gated on a matching nonce (`faulted = nonce_matches && !is_construct && status == Some(LaneStatus::Environment)`, `crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:1259`); and intake refuses it on every stage but the aggregate review (`crates/aether-chassis-bloomery/src/bloomery/intake/admit.rs:465`). The consequence is that no machinery failure the *host* observes can ever be reported as one. A child that writes no evidence, a body that will not parse, a lost capture, a signal-killed process — each is a host-side observation, and each is folded into `StageVerdict::VerificationFailed` carrying `VerifyFailureSet(0)`.

ADR-0176 named this debt when it ratified the fault lifecycle for one stage and left the rest: "Other stages must refuse `ExecutorFault` until a later decision gives them lifecycle semantics." This is that later decision, and the bill for deferring it came due on 2026-08-14.

### The incident

Bloom `392983d23800`, member `issue-4908`. The janitor deleted a live lane's cargo target directory while that lane was compiling. The directory was reclaimable by the janitor's own accounting because the warm per-slot target trees stood permanently over budget — roughly 100 GB against the 64 GiB ceiling `JanitorPolicy::lane_target_budget_bytes` sets (`crates/aether-chassis-bloomery/src/bloomery/reactor/janitor/sweep.rs:39`, default `68_719_476_736` at `crates/aether-chassis-bloomery/src/bloomery/config.rs:239`). Over-budget was therefore the steady state rather than a spike to ride out, and the sweep's only remedy is removal of every slot target directory at once (`sweep_targets_if_over_budget`, `crates/aether-chassis-bloomery/src/bloomery/reactor/janitor/sweep.rs:285`, deleting through `remove_abandoned` at `:384`).

That sweep is guarded, and the guard is the reason a live lane could be caught by it. The target-directory pass is skipped entirely when `request.lanes_running` is true (`crates/aether-chassis-bloomery/src/bloomery/reactor/janitor/sweep.rs:99`), a single process-wide boolean sourced from `any_lane_running`, which reports whether this coordinator's own registry holds any run (`crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:1314`). A child this process cannot see is not in that registry, and the pipeline has a documented way to arrive at exactly that state: a lane re-adopted after a coordinator restart keeps no handle on its child, so cancelling one logs that the child "cannot be terminated by this process and may still be running" and returns success anyway (`OrphanedRun::kill`, `crates/aether-chassis-bloomery/src/bloomery/executor/local/orphan.rs:79`), and an orphan's liveness is probed by the mere existence of an evidence file (`crates/aether-chassis-bloomery/src/bloomery/executor/local/orphan.rs:52`). A compile that is genuinely running while no registry entry says so leaves the sweep believing the machine is idle. The sweep's per-item liveness checks on worktrees and evidence (`crates/aether-chassis-bloomery/src/bloomery/reactor/janitor/sweep.rs:186`, `:245`) have no counterpart here: nothing maps `slot-N-target` back to whoever holds slot N.

From there every component behaved as designed, and the design produced the wrong outcome at each step. The compile died on a deleted incremental file, the lane exited before it reached `verify.check`, and no `evidence.json` was written. The backend failed closed: an exited run that left no readable evidence is warned about and then given a synthetic envelope carrying `StageVerdict::VerificationFailed` and `VerifyFailureSet::EMPTY` (`synthesized_missing_evidence`, `crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:995`, reached from the read arm of `stream_evidence` at `:1166`).

Intake refused precisely that shape. ADR-0178's transport invariant holds that a failed member `Verify` must name which verifiers failed, so `verifier_failure_refusal` requires `!upload.failed_verifiers.is_empty()` for that stage and verdict pair and otherwise returns `IntakeRefusal::InvalidVerifierFailures { stage: Verify, verdict: VerificationFailed, failed_verifiers: VerifyFailureSet(0) }` (`crates/aether-chassis-bloomery/src/bloomery/intake/admit.rs:189` and `:95`). The refusal was right — an empty set claims verification failed for no nameable reason, which is not a verdict worth journaling — but a refused upload leaves its order live, so nothing entered the journal at all. The order sat until its sealed wall clock, the one hour every stage binding carries (`crates/aether-bloomery/src/values/stage.rs:441`, with `StageCatalog::binding_of` calibrating every arm at `3_600` seconds per the note at `:404`), was cancelled by `expire_overdue_orders` (`crates/aether-chassis-bloomery/src/bloomery/reactor/executor/runtime/mod.rs:315`), and was recorded as a failed `Verify` attempt. The member routed into `Refine`, the repair stage, as though a gate had found faults in its candidate.

The candidate was intact and complete. Three `Refine` laps were dispatched against it, the stage's full budget (`crates/aether-bloomery/src/values/stage.rs:444`). Each found the work already done and said so, and each was recorded as a failure by a second mechanism entirely. A member lane's `Transformation` carries `diff_base: None` for every stage but `Verify` (`crates/aether-bloomery/src/values/stage.rs:768`), and that field's own documentation explains what `None` means: it "names the working tree: the candidate is the uncommitted change the checked-out tree carries, which is what every member lane produces" (`crates/aether-bloomery/src/values/stage.rs:657`). The lane was checked out at the candidate commit, so the tree was clean, so a lane that correctly changed nothing produced an empty diff. Both readings of that tree then fail closed. The child stamps `produced_candidate: false` from its own `git status` (`xtask/src/transform/construct.rs:115`), and the host takes a second, independent reading in its own trust domain, where `capture_candidate` warns that a "passed run left a clean worktree — nothing to capture, failing closed" and returns nothing (`crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:859`). A concluded construct run without a capture is downgraded to a failure at `crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:1244`. The model's verbatim answer, three times, at fifteen turns and $0.18 each, was *"Cannot proceed: the sealed subject already implements this work order in full."* It was right on every lap and was charged for being right on every lap.

Recovery then cost the remaining budget, for a structural reason. `Fact::OperatorRepair` describes the correct response almost exactly — an operator supplies a candidate, and "the candidate re-enters at `Verify` and faces the ordinary chain, so a bad operator fix bounces exactly where a bad lane's does; only the model lap is skipped" (`crates/aether-bloomery/src/reduce/event.rs:403`, with the reducer re-entering at `StageId::Verify` on the operator's tree at `crates/aether-bloomery/src/reduce/operator.rs:293`). That door is reachable only for a wedged workpiece (`crates/aether-bloomery/src/reduce/operator.rs:275`), and reaching a wedge means exhausting the retry budget. The only path to the door that costs no model lap ran through three model laps that could not possibly help.

None of this was a component behaving badly. The backend failed closed, intake refused a malformed claim, the reducer spent the budget the catalog authorized, and the model answered honestly. The loss came from the fact that no participant could say *which kind* of failure it had seen, so each defaulted to the most expensive interpretation available.

ADR-0189 is the precedent for the shape of the answer. A cross-member fold collision had been a reactor-side refusal in prose that stalled the bloom with nothing in the journal; that decision turned the stall into a fact, gave it a named stage with its own budget, and ended it at a wedge carrying the evidence that started it. The instinct — a recognized stall earns a designed recovery rather than falling through to the generic one — is right, and this decision generalizes it from one named stall to the class that contains it.

## Decision

The pipeline prefers stalling to destroying, and resuming to restarting. A stall is visible, cheap, and recoverable; destroyed work and re-run models are none of the three. Every rule below follows from that ordering.

1. **A failed attempt names its cause before the reducer chooses a response.** The completion signal stops being a bare boolean and carries a classification: `ArtifactRejected`, meaning something judged the artifact and found it wanting, or `MachineryFailed`, meaning no judgment was rendered. Absent or unreadable evidence, an unparseable evidence body, a nonce that does not match, an envelope claiming `VerificationFailed` with an empty `VerifyFailureSet`, a child that exited on a signal, a cancelled order that reached its wall clock without reporting, and a lane whose slot was reclaimed underneath it are all `MachineryFailed`. The classifier lives at the executor and intake boundary, where the raw observation is; the reducer keeps deciding advance, retry, and wedge, so ADR-0149's division of labour is unchanged and the host still reports rather than decides. A `MachineryFailed` attempt may never consume a model lap.

2. **The classification is what the host observes, not only what the child claims.** Today's `LaneStatus::Environment` is stamped by the lane body itself, which cannot report a failure that killed it, and is refused for the construct lane besides. The host's own observations become first-class sources of a machinery classification: the missing-evidence synthesis at `crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:995` reports one instead of manufacturing a verdict, and the child's exit is inspected for a terminating signal rather than folded into a boolean. `RunLifecycle::Exited { success: bool }` (`crates/aether-chassis-bloomery/src/bloomery/executor/local/runner.rs:83`) makes a signal-killed child, a clean exit 1, and a `try_wait` fault indistinguishable at `crates/aether-chassis-bloomery/src/bloomery/executor/local/process_runner.rs:514`; the first and third are machinery and the second is not, so the lifecycle carries enough to tell them apart. The lane's self-report remains a valid input and stops being the only one.

3. **Machinery retries are free, bounded, and accounted on their own axis.** An infrastructure death is not evidence that a model is failing, so it must not spend the ledger that measures whether a model is failing — the argument ADR-0176 made for the aggregate review, applied per member. A machinery failure re-dispatches the same stage against the same artifact with its own budget, drawn from the stage binding the way ADR-0176 draws its fault ceiling: the same sealed numeric calibration, an independent counter. The member's `attempts` cursor does not move, its `repair_rolls` do not move, and its candidate does not move.

4. **Re-entry starts from the newest artifact, never from the base.** A machinery retry re-runs the gate over the candidate the member already holds, and a rejected artifact refines on that same candidate with findings attached. Candidates are content-addressed and carry their own checkout commit, and `reconcile_or_line_targets` (`crates/aether-bloomery/src/reduce/attempt.rs:393`) already resolves dispatch targets from the candidate whenever one exists, so this constrains the existing target resolution rather than adding machinery. Nothing re-derives work a surviving artifact already contains.

5. **The escalation ladder is explicit, and each rung names its cost.**

   ```
   machinery failed → same stage, same artifact, no model      (free)
                    → N times → wedge, cause: MACHINERY
   work rejected    → refine on the artifact, with findings     (one model lap)
                    → budget → wedge, cause: WORK
   wedge            → operator doors: repair / grant / adjudicate / supersede
   ```

   A wedge records which of the two exhausted it. The distinction matters at the door: a `MACHINERY` wedge tells an operator to repair a host and re-enter, and a `WORK` wedge tells them the model could not do the job. Today both arrive as the same terminal state, and the operator reconstructs the difference from logs.

6. **`repair` and `grant` become reachable from any non-terminal state, with the reducer refusing what does not apply.** These two are the wedge-gated doors — `reduce_grant_attempts` refuses a workpiece the record does not hold as wedged (`crates/aether-bloomery/src/reduce/grant.rs:58`), and `reduce_operator_repair` does the same (`crates/aether-bloomery/src/reduce/operator.rs:275`). The precondition was reasonable when a wedge was the only recognized stall, and the incident shows its cost once other stalls exist: the cheapest correct response sat behind the most expensive wrong one. The remaining doors already demonstrate the target shape and need no change — `reduce_operator_adjudication` gates on an open finding or a review park rather than on a wedge (`crates/aether-bloomery/src/reduce/operator.rs:107`), `reduce_supersede` gates on a predecessor that is `Sealed` or `Resolved` (`crates/aether-bloomery/src/reduce/seal.rs:300`), and the operator brake is described as the move for a bloom that is "*suspect* rather than stopped", explicitly acting before one "has already run out of road" (`crates/aether-bloomery/src/reduce/event.rs:420`). A door's applicability becomes a stated reducer refusal rather than an unreachable state, which also makes an inapplicable door legible: an operator learns why a move does not apply instead of finding no move at all. Every other guard stands untouched, including the immutability rule — `repair` is already refused for a workpiece that has resolved (`crates/aether-bloomery/src/reduce/operator.rs:290`), matching ADR-0191 §4, and reviewed work stays closed to every door.

7. **A lane can terminally answer that its order is already satisfied.** The absent-candidate signal conflates a lane that failed with a lane that found nothing to do, and the two deserve opposite responses. Both existing readings are `git status` over a worktree — the child's `produced_candidate` stamp (`xtask/src/transform/construct.rs:115`) and the host's `capture_candidate` (`crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:859`) — so neither can express the difference between an empty diff that means failure and one that means completion. A lane that determines the sealed subject already satisfies its work order returns that as a verdict in its own right, distinct from both success and failure. The member resolves on the candidate it holds, or — when the base itself satisfies the order and no candidate exists — resolves with an explicitly empty contribution the fold treats as a no-op. The claim faces `Verify` like any other, so a lane cannot talk its way past the gates; it can only decline to author a diff it does not believe in. The answer is recorded in the study ledger, which turns "sealed work that was already done" from an expensive silence into a measurable scoping signal.

8. **Liveness is a heartbeat and a deadline, not a deadline alone.** The only liveness signal today is the absolute per-order deadline computed at dispatch and swept by `expire_overdue_orders` (`crates/aether-chassis-bloomery/src/bloomery/reactor/executor/runtime/mod.rs:315`), so a lane that dies quietly costs its full hour. The lane already streams to `transcript.jsonl` (`xtask/src/transform/lane.rs:122`), and nothing reads that file's modification time, which makes it a heartbeat available for the cost of looking at it. A lane silent for a stated interval is classified `MachineryFailed` and re-dispatched on the machinery axis; the wall clock stays as the outer bound on a lane that is alive and unproductive. This narrows the loss from a wedged host to the heartbeat interval, and it separates a lane that died from one that is merely slow — which a deadline alone cannot do, since both reach it the same way. The same signal is what a re-adopted orphan lacks, its liveness currently being inferred from whether an evidence file exists yet (`crates/aether-chassis-bloomery/src/bloomery/executor/local/orphan.rs:52`).

9. **Resource exhaustion back-pressures rather than destroys.** No reclamation may touch storage a live dispatch owns, and "live" is decided per slot rather than by one process-wide boolean: the target sweep resolves each `slot-N-target` to whoever holds slot N, the way the worktree and evidence passes already resolve their items (`crates/aether-chassis-bloomery/src/bloomery/reactor/janitor/sweep.rs:186`, `:245`). When there is no room for a new lane, the coordinator declines to dispatch one and says so, and the bloom waits. A pipeline that cannot start work is stalled and legible, whereas one that destroys work in flight converts a capacity problem into a correctness problem several layers away, which is the translation that made this incident expensive. A ceiling the steady state exceeds is a capacity fault to report, not a workload to delete into compliance.

10. **A lane belongs to the process that can signal its child.** A coordinator that has re-adopted a lane it cannot terminate does not own that lane, and treating that case as ownership is what leaks children across restarts and what lets the janitor believe the machine is idle. The dispatch record carries the child's process identity durably, so a successor coordinator either adopts a lane it can genuinely signal or declines to; a lane it cannot signal is classified `MachineryFailed`, and its slot is quarantined rather than handed to a new dispatch that would contend with a process still running in it. `OrphanedRun::kill` stops reporting success for a cancellation it did not perform (`crates/aether-chassis-bloomery/src/bloomery/executor/local/orphan.rs:79`). Quarantine is the stalling-over-destroying rule applied to a slot: withholding it is recoverable, and reusing it under a live stranger is not.

11. **Wire consequences, stated exactly.** `Fact`, `Decision`, `Outcome`, and `EvidenceKind` are wire-frozen and extend by tail-append only, each new variant appended past the current last so prior discriminants are unchanged — the convention every recent variant states in its own doc comment. This decision requires:

    - **No append to `EvidenceKind`, and no append to `StageVerdict` for the classification itself.** `StageVerdict::ExecutorFault` and `EvidenceKind::ExecutorFault` already exist and already carry these semantics. What changes is the admission gate at `crates/aether-chassis-bloomery/src/bloomery/intake/admit.rs:465`, which stops confining the verdict to `AggregateReview` and admits it for the dispatched member stages, discharging ADR-0176's stated debt; and the backend's `faulted` condition at `crates/aether-chassis-bloomery/src/bloomery/executor/local/backend.rs:1259`, which stops excluding the construct lane and stops depending solely on the child's self-report. The satisfied-order answer of §7 does require one appended `StageVerdict` variant, since no existing verdict means it.
    - **Appends to `Fact`** for the per-member machinery fault — the member analog of `Fact::AggregateReviewExecutorFault` (`crates/aether-bloomery/src/reduce/event.rs:343`) — and for the satisfied-order resolution, both appended past the current final variant, `Fact::OperatorRelease`.
    - **Appends to `Outcome`** for the machinery-retry and satisfied-order results the reducer returns.
    - **A `GOLDEN_DECISIONS` repin in the same diff.** The machinery counter and the wedge cause live on the member cursor, and the fixture's tripwire states that "adding a field to `StageProgress` … must fail here" (`crates/aether-bloomery/tests/golden_decisions/main.rs:295`). The repin carries the standard note recording that the delta is additive and confined to the tail, as every prior repin does. `Decision` gains no variant if the machinery counter folds off the existing `Decision::RecordEvidence`, the way ADR-0176 folds its fault series; whichever way the implementation resolves that, the fixture is repinned in the same change.

## Consequences

- The two rows the table answered wrongly become right. A gate that could not run re-runs over the artifact it never judged, and a lane that finds its order already met advances instead of refining against a candidate nobody faulted. The specific loss in bloom `392983d23800` — three model laps, a spent budget, and an unreachable correct door — has no path to recur, because none of its steps is reachable without a classification that permits it.
- Retry budgets start measuring what their names claim. A `Verify` budget of three becomes three judgments of a candidate rather than three attempts that a bad afternoon on a host can consume without judging anything, which makes the budgets calibratable. ADR-0184 measures blooms from the journal, and it has been measuring a mixture.
- Wedges become diagnosable at a glance, and the two operator doors that were gated on one become available during a stall rather than only after it. The cost is that a door can now be aimed at a bloom mid-flight, so each needs a stated refusal for every state it does not apply to — a larger reducer surface, and a real one, though the alternative is the unreachability the incident paid for. Those refusals are pure reducer decisions and testable as such.
- Machinery retries are free of model spend and not free of wall clock. A genuinely sick host will cycle a stage against its machinery budget and reach a wedge, where before it burned a model budget and reached a wedge; the run takes longer to give up and costs less to have tried. A machinery budget set too generously converts a fast expensive failure into a slow cheap one, which is better without being good, so the ceiling wants calibrating from the same ledger as everything else.
- Back-pressure trades throughput for safety and will sometimes idle the pipeline. A coordinator that declines to dispatch when storage is exhausted stalls a bloom that today would have run — by destroying another lane's work, but it would have run. The steady-state overage behind this incident becomes a visible refusal to dispatch rather than background churn, which surfaces a capacity problem rather than creating one, and it will need answering with capacity rather than with policy.
- Per-slot liveness in the janitor is strictly more code than one boolean, and it fails in a new direction: a slot wrongly believed live is never reclaimed, so a bookkeeping leak now shows up as disk exhaustion rather than as deleted work. That is the trade this decision makes everywhere, stated here rather than left to be found.
- Slot quarantine shrinks the usable pool after a restart that leaves unsignalable children behind, so a pathological restart cycle could starve the pipeline of slots. The quarantine needs an operator-visible release, and until one exists the failure mode is a stall.
- The classification is a new place to be wrong. A misclassification toward `MachineryFailed` retries a genuinely bad artifact for free and delays an honest wedge; one toward `ArtifactRejected` reproduces exactly today's behaviour. The asymmetry is deliberate, since the second error is the one being paid for now and the first is bounded by the machinery budget.
- `StageVerdict::ExecutorFault` becomes reachable from the dispatched member stages instead of the aggregate review alone, so the lane-boundary coverage ADR-0176 required is now required per stage: redispatch below the ceiling, terminal observation at it, and no member repair counter moving in either case.

## Alternatives considered

- **Keep one failure bit and raise the retry budgets.** The cheapest change and a strict worsening of what hurt. Larger budgets buy more laps of the response that could not have helped, so the incident's cost rises linearly while its structure stays intact — three futile `Refine` laps become six. It also degrades the budgets as a measurement, since a number inflated to absorb infrastructure noise says nothing about model competence, which is the one question a retry budget exists to answer.
- **Make the operator doors ungated and rely on operators to notice.** This is §6 without §1 through §5, and it repairs the last step of the incident rather than the first. An operator would have reached `repair` without spending three laps, but only by watching a bloom closely enough to catch a stall that nothing announced — and the pipeline exists so that recovery from a machinery failure does not depend on a human being awake. It also leaves the pipeline unable to perform for free a retry it is perfectly capable of performing, converting every transient host fault into an operator interrupt.
- **Treat every infrastructure failure as a supersession.** Sound at the top of the ladder and ruinous at the bottom. A supersession discards in-flight state and re-seals, so a deleted target directory would cost every member's progress rather than one gate re-run — the maximal answer applied to the minimal failure, and precisely the destroying-over-stalling the governing principle rejects. ADR-0176 already reaches for supersession as the terminal answer once a fault budget is exhausted, which is the right altitude for it; making it the first response inverts the ladder.
- **Have the host retry machinery failures silently, without a journaled fact.** Tempting because it needs no wire change, and rejected on ADR-0149's terms: state the journal does not record cannot be replayed, bounded, or observed, so a host quietly re-running a gate would be an unbounded invisible loop the study ledger could not price and a restart would forget. The point of ADR-0176's counter is that a fault series survives process restarts.
- **Infer machinery failure in the reducer from the shape of the evidence.** The reducer could read an empty `VerifyFailureSet` on a failing `Verify` as a machinery signal, with no classification travelling on the fact. This recovers one case and misses the rest — a signal-killed child, a silent lane, a reclaimed slot, and an unparseable body leave no evidence to inspect — and it makes the reducer reconstruct what the executor observed directly. The classification belongs where the observation is, which is where ADR-0176 put the aggregate review's.
- **Widen the existing `LaneStatus::Environment` to the construct lane and leave the rest alone.** The smallest move that touches the right mechanism, and insufficient because the signal is self-reported: it asks a child to describe machinery failures that terminate it, which is the class this incident consisted of. It also leaves the intake gate, the budget separation, and the wedge cause untouched, so a fault admitted for a member stage would still spend the repair ledger it must not spend.
