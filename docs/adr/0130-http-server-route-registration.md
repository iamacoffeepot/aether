# ADR-0130: HTTP Server Route Registration

- **Status:** Accepted (shipped — HTTP server route registration in `crates/aether-http/src/server/mod.rs`)
- **Date:** 2026-07-03

Extends **ADR-0108** (the `aether.http.server` capability), realizing the routing refinements its §Follow-on parked. Mirrors the declare-interest-by-mail model of **ADR-0021** / **ADR-0083** (input-stream subscriptions) and rides the shared lifecycle `wire` hook of iamacoffeepot/aether#2048. Composes unchanged with **ADR-0128** (response streaming) and **ADR-0129** (websocket upgrade), both of which act downstream of dispatch, keyed by the request's correlation.

## Context

ADR-0108 ships single-handler dispatch: every inbound request goes to the one configured `handler_mailbox`, and a multi-route endpoint expresses its routing as a `match` on `path` inside that handler. The ADR's §Follow-on parks two refinements — a path/prefix route table, and typed-kind routing that hands a component its own domain kind instead of the generic `aether.http.server.request`.

The first attempt at the route table (iamacoffeepot/aether#2549, PR #2557) shaped it as operator boot config: an `AETHER_HTTP_SERVER_ROUTES` env knob of `"<prefix>=<mailbox>"` entries. Review rejected that shape. Routing knowledge belongs to the component that serves the route, and the config table puts it with the operator instead: lineage names duplicated into an env string that must track what is loaded, a table frozen at boot that a mid-session `load_component` cannot join, and exactly the awkward-authoring cost ADR-0108's own §Alternatives recorded when it declined config-table routing for v1.

Three properties of the substrate shape the replacement:

- **The engine already carries the right primitive.** Input-stream subscriptions are declare-interest-by-mail: a component subscribes from its `wire` hook, the reflexive kind resolves the subscriber from the host-stamped envelope `Source` (forgery-proof, in-process by construction), the cap keys its table by `MailboxId`, and the component capability's `on_drop_component` purges the tables of dropped components by fanning out `UnsubscribeAll`. Since iamacoffeepot/aether#2048 hoisted `wire` onto the shared `Lifecycle<S>` trait, the same registration moment exists for native actors and wasm components alike.
- **Kind-keyed dispatch is the actor's one demuxer.** `#[actor]` rejects two `#[handler]`s for the same kind (a second arm would shadow), so per-function routing inside a component cannot be expressed against a single request kind — the demand for "this route, this function" is a demand for one kind per route.
- **The dispatch site is already envelope-level.** The cap sends the handler its request via `send_envelope_as_root(handler, kind_id, &payload)` — the kind id is runtime data, so stamping a route-specific kind onto the request-shaped payload costs one argument.

## Decision

Routing is a mail-driven registration protocol on the `aether.http.server` mailbox, and a route names the kind its requests dispatch as.

**Registration kinds.** Six public kinds join the `aether.http.server.*` family, mirroring the `aether.input` subscribe family: `register_route` / `register_route_self`, `unregister_route` / `unregister_route_self`, `unregister_routes_all`, and the `register_route_result` reply. The `_self` variants resolve the registrant from the host-stamped envelope `Source` — forgery-proof and gated to in-process actors by construction; the explicit-`mailbox` variants serve external callers (MCP, tests) and validate the mailbox against the registry before accepting. A registration carries `{ prefix, method, kind }`: the path prefix, an optional `HttpMethod` filter, and the `KindId` the route's requests dispatch as (`aether.http.server.request` itself for a handler that wants the generic shape).

**Route table and matching.** The cap keys routes by registrant `MailboxId` — no names in the table, so a route survives `replace_component` (the mailbox id is stable) and dispatch skips name resolution. Prefix matching is segment-boundary: `/api` matches `/api` and `/api/…`, never `/apiary`; `/` is the catch-all. Among routes whose method filter accepts the request, the longest prefix wins, and a method-specific route beats a method-agnostic one at equal prefix. Conflict policy: a second registrant claiming an already-held `(prefix, method)` key is answered `register_route_result::Err` — loud, and harmless to the common re-registration case, where the same mailbox re-claiming its own key is an idempotent `Ok`. A request matching no route falls back to the ADR-0108 `handler_mailbox`; an empty or unresolved fallback keeps today's `503`. The table empty means every request takes the fallback path — the protocol is purely additive over shipped deployments.

**Route-as-kind dispatch.** At dispatch the cap encodes the usual request payload and stamps the route's registered `KindId` on the envelope. The registered kind's schema must decode `aether.http.server.request`'s byte layout — the route-kind minting surface (below) is the sanctioned way to satisfy that; a violation fails decode at the receiver, the chain settles response-less, and the existing `502` settlement net answers. Kind-keyed dispatch then gives each route its own `#[handler]`, its own `describe_component` entry, and its own `actor_cost` row.

**Cleanup.** The component capability's `on_drop_component` fan-out gains `unregister_routes_all` alongside its existing `UnsubscribeAll` / `LifecycleUnsubscribeAll` sends, guarded on the http server actually being booted (the cap registers only when a bind is configured, so the guard is a registry lookup, the sanctioned runtime-name path).

**Typed routing is guest-side.** This ADR forecloses cap-side field extraction: the cap's routing vocabulary is `prefix → kind` and the wire payload for a routed kind is always request-shaped. The typed layer lands as guest/native-shared glue in a follow-on arc: a `FromRequest` trait (`fn from_request(&HttpServerRequest) -> Result<Self, HttpServerResponse>`, the `Err` being the response to send — typically a `400`), an `http::Ctx<'a, C>` wrapper over the transport ctx exposing the original request and matched route (total, because the request always crosses the wire), and an `#[http::router]` / `#[http::route]` authoring surface that mints the hidden route kinds and generates the handler glue, over both transports. Field extraction expressed as `FromRequest` impls is ordinary type-checked Rust; expressed as cap config it would be an extraction language the substrate has to own, version, and validate.

## Consequences

- **Positive** — a component owns a path family by declaring it in `wire`, next to its input subscriptions; no central `match` funnel and no operator-maintained route string. Routes follow the component through reload and `replace_component`, and a component loaded mid-session serves its routes immediately. Each route is a distinct kind, so dispatch, introspection (`describe_component`), and cost attribution (`actor_cost`) are per-route for free. Both parked ADR-0108 refinements land as one protocol: the table is the registration state, and typed routing is the kind the route names.
- **Neutral / cost** — six new public kinds and a registration table plus its handlers on the http server cap; the component capability's drop fan-out gains a third target; dispatch adds a route resolution scan (linear over a sorted route set; route counts are tens per substrate, and the scan is dwarfed by the header parse that precedes it).
- **Negative / risk** — a request arriving before a component's `wire` has run takes the fallback, the same window input events have before a subscribe lands (accepted; boot-time routes belong to the fallback handler). A wedged component leaves its routes answering through a dead mailbox until it is dropped — the same surface as a dead `handler_mailbox` today, and the drop fan-out clears it. Route state is runtime-only: a substrate restart forgets routes until components re-`wire`, consistent with every other subscription table.
- **Follow-on** — the authoring-surface arc (`FromRequest`, `http::Ctx`, the router/route macros, native-side test fixtures written against the macro surface) is its own issue and PR. ADR-0128 streaming and ADR-0129 websocket upgrade need no changes: both key off the dispatched request's correlation and are indifferent to which route selected the handler.

## Alternatives considered

- **Config route table** (`AETHER_HTTP_SERVER_ROUTES`, PR #2557) — operator-owned and boot-static; duplicates lineage names into env config, cannot serve mid-session loads, and pays the awkward-authoring cost ADR-0108 §Alternatives already recorded. Rejected on review.
- **In-payload demux** (one handler, `match path`) — the shipped v1 shape; it centralizes routing in a funnel and cannot reach per-function dispatch, because duplicate handler kinds are rejected by design.
- **Cap-side field extraction** (route → domain kind encoded by the cap) — requires an extraction config language on the substrate; `FromRequest` impls express the same mapping as type-checked Rust in the component that owns the meaning. Foreclosed, not deferred.
- **Userspace router component** — a component that receives everything and forwards re-centralizes the `match` and adds a hop; it remains possible in userspace but is not the sanctioned multi-handler surface.
- **Lifecycle-stage cleanup** — there is no component-death broadcast stage (lifecycle stages are tick-schedule stages), so the component capability's drop fan-out is the established purge seam.
- **First-match-wins ordered table** — registration arrival order is nondeterministic across boots; longest-prefix with the method tiebreak is deterministic and subsumes exact match and the `/` catch-all.
