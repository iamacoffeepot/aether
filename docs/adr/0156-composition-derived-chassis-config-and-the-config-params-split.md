# ADR-0156: Composition-Derived Chassis Config and the Config Params Split

- **Status:** Proposed
- **Date:** 2026-07-21

## Context

ADR-0090 gave capability config its resolution machinery: `#[derive(aether_substrate::Config)]` emits the env-shaped layer, the clap-shaped overlay, and the confique `META`, resolved argv > env > file > defaults. ADR-0155 named the chassis boot stages (Compose / Claim / Init / Wire / Start) and derived the `--describe` capability roster from the Claim stage of the real registration path; its consequences forecast the follow-on arc: dissolving the per-chassis Env bags into per-capability resolution.

The chassis config surface is that forecast's target. It is assembled today in three hand-maintained mirrors of the composition: the per-chassis Env resolver (one `resolve_with_file::<C>(overlay, file, "section")` line per config, section names as chassis-side string literals), the `chassis_registry()` const list of `*Layer::META`s feeding the known-keys sweep and `--print-config` (with `hub_chassis_registry()` hand-special-cased on top), and the clap CLI roots. All three carry the disease ADR-0155 diagnosed for the capability roster, in both directions a hand list can fail. Over-claim: the registry is one flat list shared by desktop and headless, so the headless known keys and dump include window, audio, and render-tuning knobs it never composes, and the desktop set includes the tick knob — a stale `AETHER_WINDOW_MODE` on a headless box passes the unknown-key sweep silently. Under-claim: `InputCapability` and `GameGatewayCapability` are composed on every full-stack chassis with `::default()`-only configs — no META, no file section, no overlay; membership decided by nobody.

The root cause is one associated type doing two jobs. `Lifecycle::Config` means only "the value Init consumes" (`Send + 'static`): nothing marks a config as operator-resolvable, the section names live chassis-side, and several `Config` types carry construction wiring rather than config. `ComponentHostConfig` is three `Arc`s (engine / linker / outbound); `RpcServerConfig` mixes the resolved bind address with peer identity and route-target wiring; `GeminiBoot` carries a staging root derived from two other resolved configs; `RenderConfig` carries a harness observability `Arc`; `LifecycleConfig` carries the chassis-declared stage graph; `GameGatewayConfig` carries a resolved `MailboxId`. Because the conflation is unexpressed, no aggregate "everything configurable on this chassis" can be derived from the composition — and beside the derive path, a residue of knobs is still read from bare env (`AETHER_RPC_PORT` inline in the chassis bins, `AETHER_MAX_FRAME_SIZE` pull-read in five crates, the runtime log / crash knobs), registered as hand `KnobRecord`s so the sweep tolerates them.

## Decision

Make the chassis config a value derived from Compose: every composed actor declares its operator-resolvable config, the builder resolves every member from one source stack, and the aggregate — the chassis config — is queryable the moment the chassis is composed. This extends ADR-0090 (source stack, derive vocabulary) and builds on ADR-0155 (stage vocabulary, the claim-terminal precedent, the §4 config-versus-handles rule) without superseding either.

**1. `Lifecycle` splits the init input into `Config` and `Params`.** `type Config` is the operator-resolvable member; `type Params` is the composer-supplied construction input. The factory becomes `init(config, params, ctx)` on both transports. The `#[actor]` macro synthesizes `type Params = ()` when the author omits it — the same stand-in it already provides for `Persist` — so a channel-less actor pays nothing.

**2. Per-transport bounds say what each channel can hold.** On `NativeActor`, `Config` is a `#[derive(aether_substrate::Config)]` type — bringing its section name, layer, overlay, and `META` with it — or `()` for a configless cap; `Params` stays `Send + 'static` (live values are legal because the composer shares the address space) and rides `with_actor::<A>(params)`, so a missing dependency stays a compile error (the `CommonBoot` flat-struct acknowledgment property, kept). On `WasmActor`, `Config` keeps its `Kind + Default` bound and `Params` is bounded `Kind`: both channels cross the FFI as bytes, and the split is authorship — config bytes come from the operator's staged file, params bytes are synthesized by the component host at load time. Every current component ships `Params = ()`; the first real payload (replica identity — index and count under `replicas: N`, whose instances share one config by contract and today have no principled source for their own index) is a named follow-up, not part of this arc.

**3. Config is data an operator could type; everything else is evicted.** The membership test for `Config` is: declarable as a simple parsable value in a config file. What fails the test moves to `Params` (the component host's `Arc`s, the RPC peer identity and route target, the lifecycle stage graph, the gateway's resolved `TurnSim` mailbox) or — when it cannot exist at Compose on every host — to the Start-stage handle channel ADR-0155 §4 already established (the desktop capture backend, harness observability hooks). Actor references in `Config` are names resolved at Wire; a resolved `MailboxId` is by definition `Params`. A value derived from other members (the gemini staging root, computed from the contentgen override and the fs save root) is computed at Init from resolved members and held by no config.

**4. The chassis config is the aggregate, derived at Compose.** Chassis config = the union of the composed actors' `Config` declarations — drivers declare theirs the same way, so the tick knob belongs to the headless timer driver and the window knobs to the desktop driver — plus the chassis-declared members that configure the shared base rather than any single cap: workers, ring capacities, scheduler tuning, teardown cap, boot manifest. A `Builder::config_manifest()` terminal, sibling to ADR-0155's `claim_namespaces()`, walks the composed entries and returns every member with its section, keys, defaults, docs, and resolved values. The known-keys sweep, `--print-config`, and the file-section vocabulary all read this walk; `chassis_registry()`, `hub_chassis_registry()`, and their lockstep tests are deleted.

**5. Resolution inverts: compose, then resolve.** `with_actor` stops carrying resolved config values; the builder resolves each member from one source stack ahead of Init. The stack gains an explicit top layer: programmatic > argv > env > file > default. The programmatic layer is how tests and the harnesses keep constructing config values directly in code — an explicit-value layer inside the stack rather than a bypass around it.

**6. No knob lives on bare env.** Every knob is a field of some chassis config member. `AETHER_RPC_PORT` becomes a field of the RPC server cap's `Config` (deleting the inline read and its hand record); `AETHER_MAX_FRAME_SIZE` becomes a chassis-declared member whose resolved value is pushed set-once into `aether-codec` (deleting the five pull-reads); the runtime knobs (log filter, backtrace, crash log) become chassis-declared members resolved before Compose by the same machinery, re-applied after file-layer resolution where a late value matters. The sole survivor outside the aggregate is `--config` / `AETHER_CONFIG_FILE`, the meta-knob that selects the file source and therefore cannot live in the file; it stays one declared, documented `KnobRecord`. The hub's fleet pass-through (fleet cap keys legitimately in the hub's env, destined for spawned substrates) stays the one declared over-approximation.

## Consequences

- An operator or agent can ask any composed chassis what is configurable and get a complete, drift-proof answer; a typo'd knob fails the sweep honestly on every chassis (headless stops "knowing" window knobs).
- The Env-resolver and registry mirrors are deleted; membership drift becomes structurally impossible. The CLI roots stay hand-written static clap structs but become checkable — an assertion that the root's flag set equals the composed members' overlay set replaces the lockstep comment.
- The migration is wide but shallow: wiring-bearing `Config` types rename to `Params` structs, resolvable fields move into new derive-`Config` types, and every `with_actor` call site plus both harnesses change signature.
- The `Lifecycle` trait change touches both transports; wasm components recompile with the synthesized `Params = ()` and authors write nothing.
- The per-chassis Env bags dissolve (the ADR-0155 forecast): `from_env_with_argv` shrinks to CLI parse + file load + handing the builder the source stack.
- `config_manifest()` is pre-boot only. Live config introspection over mail becomes reachable but is a named non-goal here.
- Follow-on work this creates: the codec frame-size push (set-once install replacing env pull-reads) and replica identity as the first wasm `Params` payload.

## Alternatives considered

- **A second declaration beside `Config`** (each cap separately declares its resolvable part; `Config` keeps carrying wiring) — institutionalizes the conflation and adds a per-cap lockstep, the disease under treatment; rejected.
- **A type-keyed injection map as the general wiring channel** (builder-populated store read at init) — turns a missing dependency into a runtime `BootError` where `with_actor(params)` keeps it a compile error; kept only for Start-stage handles; rejected as the general channel.
- **Derive the registry only, keep chassis-side resolution** — the aggregate exists but resolution stays one hand line per member with chassis-side section strings; half the drift remains; rejected.
- **Keep bare-env knobs as hand records** — the aggregate's completeness claim would carry footnotes, and the sweep would keep tolerating undeclared reads; rejected.
- **Blank-instance construction** (construct actors at Compose, configure them later) — Claim needs no instance (namespaces are type-level consts) and `init` already is the factory; pre-config instances would force `Default` on every actor and split initialization in two; rejected.
