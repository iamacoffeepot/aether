# ADR-0131: Typed Route Authoring Surface for the HTTP Server

- **Status:** Accepted
- **Date:** 2026-07-03

Realizes the guest-side typed-routing layer **ADR-0130** decided and scoped as its follow-on arc. Builds on **ADR-0033** / **ADR-0123** (the `#[actor]` dispatch macro and its impl-hosted / struct-hosted forms), **ADR-0121** (capabilities own their kinds), and the shared `Lifecycle<S>` hook of iamacoffeepot/aether#2048.

## Context

ADR-0130 made routing a mail-driven registration protocol: a component claims a path prefix from `wire` and names the `KindId` its requests dispatch as, and the cap stamps that kind onto the request-shaped payload at dispatch. It deliberately foreclosed cap-side field extraction — the typed layer is guest-side, and the ADR names its pieces (`FromRequest`, `http::Ctx`, an `#[http::router]` / `#[http::route]` authoring surface) without designing them. This ADR designs them.

The hand-written shape the protocol leaves behind is visible in the fixtures #2549 landed. A routed handler today mints its own request-shaped kind by duplicating all six `HttpServerRequest` fields under a new `#[kind(name)]`, sends `RegisterRouteSelf` from `wire` with that kind's `ID`, and receives the raw request shape in a `#[handler]` that hand-parses path, query, and body before replying. Three properties of that shape drive the design:

- **The duplicated kind is a silent-drift hazard.** The registered kind's schema must decode `aether.http.server.request`'s byte layout. A field-by-field copy satisfies that today and keeps compiling when `HttpServerRequest` gains a field — the mismatch surfaces only at runtime decode, as a settlement-net `502`. The sanctioned minting surface must make layout agreement structural, not copied.
- **The derives are load-bearing; a minted kind must ride them.** `#[derive(Kind)]` computes `ID` from the kind name *plus* the canonical schema bytes, and emits the `aether.kinds` / `aether.kinds.labels` link-sections and the native descriptor inventory. A macro that hand-rolls `impl Kind` by delegation would silently skip the section and inventory emission, so the minted type must be a real struct carrying the ordinary derives.
- **The glue is mechanical and per-route.** Kind minting, `wire` registration, extraction, and the error-response early-exit are the same code at every route with only the prefix, method, and parameter types varying — exactly the shape an attribute macro owns. `#[actor]` already tolerates plain non-`#[handler]` methods in its impl block (they ride the inherent impl as helpers), and attribute macros expand outer-first, so a macro *above* `#[actor]` can rewrite routed methods into `#[handler]` glue and leave `#[actor]` to build dispatch from the result.

Ownership constrains where the macros live. The vocabulary they compile down to (`HttpServerRequest`, `RegisterRouteSelf`, `HttpServerCapability`) is owned by the crate that owns the HTTP caps (ADR-0121), and `aether-actor` sits below it in the crate DAG — hosting the macros in `aether-actor-derive` would leak HTTP vocabulary into the transport SDK. Proc-macro crates cannot export runtime items, so the trait and ctx types need a non-macro home; both transports must be served, because native actors register routes exactly the way wasm components do (`Lifecycle<S>::wire`, #2048).

## Decision

A typed authoring layer in the HTTP caps' wasm-safe surface, with the proc macros in a new sibling crate.

**Crate topology.** A sibling proc-macro crate hosts `#[router]` and `#[route]`; the crate owning the HTTP caps depends on it unconditionally (proc macros are host-compiled, so the wasm-header-only build is unaffected) and re-exports both, so consumers write `#[http::router]` / `#[http::route]` next to the `http::FromRequest` / `http::Ctx` runtime types. That crate adds `extern crate self as <itself>;` so the macro-emitted absolute paths resolve inside its own test fixtures too (the pattern `aether-actor` / `aether-substrate` already use).

> **Amendment (iamacoffeepot/aether#3758).** The decision above stands; only its coordinates changed. The HTTP caps were extracted out of `aether-capabilities` into their own **`aether-http`** crate, and the proc-macro sibling — which was always entirely HTTP — was renamed from `aether-capabilities-derive` to **`aether-http-derive`**, making it a leaf under `aether-http` the way `aether-actor-derive` and `aether-data-derive` sit under their parents. The macros now emit `::aether_http::…` paths, and the self-alias moved with them: `aether-http` carries `extern crate self as aether_http;` and `aether-capabilities` carries nothing alias-shaped. Consumers still write `#[http::router]` / `#[http::route]`, reaching the macros through `aether_http` instead of `aether_capabilities::http`.

**`http::FromRequest`.** `fn from_request(request: &HttpServerRequest) -> Result<Self, HttpServerResponse>` — the `Err` is the response the glue replies with, typically a `400`. Extraction is ordinary type-checked Rust in the crate that owns the meaning, which is the whole point of foreclosing cap-side extraction. An identity-style impl for `HttpServerRequest` (clone from the borrow) covers handlers that want the raw request as a parameter.

**`http::Ctx<'a, C>`.** Wraps the transport ctx (`&'a mut C`, `Deref`/`DerefMut` to `C`) and exposes `request(): &HttpServerRequest` and `route(): Route` — the matched route's `{ prefix: &'static str, method: Option<HttpMethod> }`, compile-time constants of the handler the macro generated. Both accessors are total: routed payloads are always request-shaped (ADR-0130), and the route is known statically per glue handler. Generic over `C` rather than transport-specific, so one type serves `WasmCtx` and `NativeCtx`.

**`#[http::router]` / `#[http::route]`.** `#[http::router]` is an impl-block attribute written *above* `#[actor]` (or `#[runtime]`); outer-first expansion means it runs first, consumes the `#[http::route(<Method|any>, "<prefix>")]` attributes on methods, and hands `#[actor]` an ordinary impl block. For each routed method it emits three things:

1. **A minted route kind** as a sibling item: a `#[doc(hidden)]` single-field struct `{ request: HttpServerRequest }` carrying the ordinary `Kind` / `Schema` / serde derives, named `"{NAMESPACE}.route.{fn_name}"`. The single-field wrapper makes layout agreement structural — its wire encoding is field-concatenation, so it decodes the request payload byte-for-byte whatever fields `HttpServerRequest` grows — while the real derives keep `ID` derivation, the `aether.kinds` sections, and the descriptor inventory exactly as hand-written kinds get them. Per-route `describe_component` entries and `actor_cost` rows follow for free.
2. **A `#[handler]` glue method** receiving the minted kind: it runs each extractor parameter's `FromRequest` in declaration order, early-returning the first `Err` as the reply, then builds `http::Ctx` over the transport ctx and the decoded request and calls the retained user method. The user's routed method survives verbatim (minus the `route` attribute) as a plain helper method — unit-testable directly, invisible to dispatch.
3. **`wire` registration**: a `RegisterRouteSelf { prefix, method, kind: <Minted as Kind>::ID }` send to `HttpServerCapability`, appended to the author's `fn wire` body or synthesized as a new `wire` when the impl has none, with receiver and ctx parameter shapes copied from the routed methods' own signatures (which is what lets one macro serve both transports' `wire` conventions).

**Routed-method contract (v1).** `(&mut self | state: &mut Self::State, ctx: http::Ctx<'_, C>, <extractors…>) -> HttpServerResponse` — receiver and ctx forms as the hosting impl's convention dictates, zero or more `FromRequest` parameters, buffered response out. A streaming route (`HttpResponseStreamOpen`, ADR-0128) keeps the raw surface — register the minted or generic kind by hand and write the `#[handler]` directly — because the glue's extraction early-exit needs the error response and the success value to share a reply type. Registration replies are absorbed exactly as the shipped hand-written pattern's are; the macro injects no `RegisterRouteResult` handler, keeping the kind's one handler slot free for an author who wants explicit handling.

**Transport universality and the split-cap seam.** The rewrite is syntactic over the impl block, so the one macro serves `#[actor] impl WasmActor for X` and the impl-hosted `#[actor(<cardinality>)] impl NativeActor for X` alike. On a split native cap (ADR-0123 struct-hosted form) the `#[runtime]` impl gets correct dispatch, but the struct-side disk harvest parses source and never sees the router's expansion, so `HandlesKind` markers for minted route kinds are not lifted. Accepted: route kinds are stamped envelope-level by the cap at dispatch and are never type-addressed by senders, so the missing marker gates nothing real.

## Consequences

- **Positive** — the per-route boilerplate (hand-minted kind, `wire` send, path re-parse) collapses into one attribute per route; layout drift between a route kind and `HttpServerRequest` becomes structurally impossible rather than a runtime `502`; extraction failures become typed `400`s at the boundary instead of ad-hoc parsing inside handlers; ADR-0130's per-route introspection and cost attribution carry over unchanged because the glue is an ordinary `#[handler]` over an ordinarily-derived kind.
- **Neutral / cost** — a new proc-macro crate in the workspace, and a second macro layer whose expansion order (`router` above `actor`) is a convention authors must know; the macro reads signatures syntactically, so the ctx and receiver shapes it copies must be written out (no type inference at expansion). The http server's fixtures are rewritten against the macro surface so tests exercise what consumers author.
- **Negative / risk** — `#[http::route]` on a method whose impl lacks `#[http::router]` would otherwise die as an unresolved attribute, so `route` is defined as a real attribute macro whose expansion is a `compile_error!` pointing at the missing `router` (the attribute never survives to it under correct usage). Macro-generated glue is harder to step through than hand-written handlers; `describe_component` prose for glue handlers is macro-authored. The v1 return contract excludes streaming routes from the typed surface — deferred, not foreclosed; a later reply-class widening can lift it.
- **Follow-on** — the implementing arc rewrites the http server's native test fixtures and the `RoutedHttpHandler` wasm fixture against the surface, and extends `docs/guide/recipes/serving-http.md` with the typed authoring recipe.

## Alternatives considered

- **Field-duplicated minted kinds** (the current hand-written fixture shape) — keeps compiling when `HttpServerRequest` drifts and fails only at runtime decode; the wrapper makes agreement structural.
- **Hand-rolled `Kind`/`Schema` impls by delegation** (`SCHEMA = HttpServerRequest::SCHEMA`) — byte-exact, but skips the link-section and inventory emission the derive owns, silently degrading introspection; riding the real derives keeps one emission path.
- **Macros in `aether-actor-derive`** — puts HTTP vocabulary in the transport SDK below the crate that owns the kinds (ADR-0121); a cap-owned derive crate keeps ownership aligned.
- **A flexible return contract (`IntoRouteReply` over buffered + streaming)** in v1 — widens the public trait surface before any consumer needs it; the raw surface already serves streaming routes.
- **An injected `RegisterRouteResult` warn-on-`Err` handler** — occupies the kind's single handler slot (`#[actor]` rejects duplicates), foreclosing author-written handling; absorption matches the shipped registration pattern.
- **Runtime route builder (a `routes()` method returning a table)** — a value-level table cannot mint kinds or `#[handler]`s, so it collapses back to one-kind funnel dispatch, exactly what ADR-0130's kind-keyed design exists to avoid.
