# ADR-0159: Guest-hosted provider capabilities

- **Status:** Accepted
- **Date:** 2026-07-21

Supersedes one alternative-rejection inside **ADR-0050** (the "Caps as guest components, not substrate caps" bullet). Builds on the edge capabilities landing in **ADR-0157** (`aether.process.run`, issue #3886) and **ADR-0158** (`aether.http` per-sender bounded async dispatch, issue #3887), the init-config bytes path of **ADR-0090**, the request-context reply correlation of **ADR-0139**, and the hold-until-resolve dispatch primitive of **ADR-0093**. The companion chassis refactor is issue #3893; the two component implementations are issues #3891 (anthropic) and #3892 (gemini).

## Context

`aether.anthropic` and `aether.gemini` are native chassis-owned capabilities today (ADR-0050): each is a single-threaded actor that owns provider auth, the blocking `ureq` client (`aether-contentgen`'s shared `transport::run_request`) or the `claude` subprocess (`aether-anthropic/src/cli.rs`), the `gen/<uuid>.{png,wav}` disk staging (`aether-contentgen/src/staging.rs`), and a cap-local `TaskQueue` concurrency bound (ADR-0093). Every desktop and headless chassis links this machinery whether or not the deployment ever calls a provider, and the provider logic can only run native — a wasm guest component cannot reach it except by mailing the cap.

Two forces now push provider logic into guest space:

- **The harness vision wants provider access as a loadable actor.** Aether's direction is Claude and other actors composing in a harness, loading the capabilities a workload needs. Provider access that arrives by loading a wasm component — rather than by every chassis carrying it at boot — matches how meshes, cameras, and text already compose.
- **The pure fraction of each cap is already large and already factored.** Roughly 60–65% of each capability is provider logic with no I/O: request-body construction (`aether-anthropic/src/api.rs::build_request_body`, `aether-gemini/src/adapter.rs::build_nanobanana_body`), response parsing (`api.rs::parse_messages_response`, the `nanobanana`/`lyria` parsers), the per-model validation-string tables (`aspect_ratio_str`, `image_size_str`, `thinking_level_str`), the error taxonomy (`error.rs`, `map_adapter_error`), and the shared string helpers (`transport::parse_status_prefix`, `transport::snippet`). These are the fixture-tested functions ADR-0050 §4 built for vendor-wire-shape locking; they depend only on `serde` and `aether_data`, so they already compile to `wasm32` unchanged.

The I/O these functions sit behind — HTTPS, subprocess, disk — is now separately mail-addressable at the substrate edge, which is what makes the move possible without giving the guest a socket:

- **HTTPS** rides `aether.http.fetch` (`Fetch` / `FetchResult`, `crates/aether-http/src/kinds.rs`). ADR-0158 converts the client's inline dispatch to per-sender bounded async over the ADR-0093 `TaskQueue`, keyed on `ctx.reply_target()`, so a component's fetches queue engine-side under the cap's own settlement holds.
- **Subprocess** rides `aether.process.run` (ADR-0157): a general one-shot exec edge with a deny-by-default binary allowlist, argv-array-only invocation, and an explicitly constructed child environment. The exec-and-capture loop it standardizes is lifted from `aether-anthropic/src/cli.rs`.
- **Disk staging** rides `aether.fs.write` to the `save` namespace at `gen/<uuid>.{png,wav}` (ADR-0041). The reply keeps carrying the staged path, so `feedback_no_bytes_in_llm_json` holds — generated bytes never ride the reply.
- **Reply correlation** rides `send_with_context` / `take_context` (ADR-0139): a guest stashes a kind-typed context on the outbound request and recovers it on the reply, keyed on the envelope correlation id, the same two-handler shape `aether.kit.mesh` uses across `on_load` / `on_read_result`.

The owner has approved reimplementing both capabilities as wasm guest components on these primitives, and retiring the native runtime halves once the components reach parity.

### What ADR-0050 evaluated, and what changed

ADR-0050's "Caps as guest components, not substrate caps" bullet rejected a design where the guest owns both the API key **and** the socket/subprocess I/O, on two grounds: API-key handling inside wasm is worse security, and a per-call host round-trip adds latency.

This ADR adopts a different division of labor that ADR-0050 never weighed. The guest owns the pure orchestration logic — body building, response parsing, validation, error mapping — and holds the API key in its configured memory. The native edge capabilities own the sockets, the subprocess, and the disk. The guest reaches I/O only by mailing `aether.http`, `aether.process`, and `aether.fs`, so the socket and the child process stay native and the guest addresses them the same way any component addresses `aether.fs` today.

The rest of ADR-0050 stands unchanged: the per-provider capability grain (one capability per provider, one kind per API), the byte-identical wire kind vocabulary, the per-provider error taxonomy, the versioning-by-kind policy, and the media-outputs-are-paths modeling. This ADR changes where those kinds are handled — a loaded wasm component instead of a chassis-owned native actor — and leaves their shapes alone.

## Decision

Reimplement `aether.anthropic` and `aether.gemini` as wasm guest components. Each keeps its wire kinds byte-identical, ports its pure logic unchanged, and dispatches its I/O as mail to the native edge capabilities. Provider access becomes opt-in: a substrate that wants it loads the component; the default chassis composition carries neither.

### 1. Wire kinds stay byte-identical

The four anthropic kinds (`aether.anthropic.messages.send`, `aether.anthropic.cli.send`, and their `_result` replies) and the four gemini kinds (`aether.gemini.nanobanana.generate`, `aether.gemini.lyria.generate`, and their `_result` replies) keep their exact `#[kind(name = …)]` literals and field shapes. The kind crates (`aether-anthropic`, `aether-gemini`) already expose these types without the `runtime` feature, so a component and its callers share the same vocabulary crate (ADR-0066); the component adds a `runtime`-gated `export!` cdylib the way every wasm actor does.

No in-repo static sender addresses these kinds today, so no caller changes. A caller mails `aether.anthropic.messages.send` to the loaded component's lineage address (`aether.component/aether.embedded:aether.anthropic`) exactly as it mailed the native cap's `aether.anthropic` mailbox, and reads back the same reply kind.

### 2. Pure logic ports as-is

The request-body builders, response parsers, per-model validation tables, error taxonomy, and shared string helpers move into the component crate unchanged. They are already `no_std`-friendly and fixture-tested; the fixtures port to guest-side unit tests over the same functions. This is the 60–65% of each capability that carries no I/O.

The base64 request-side encoder (`aether-gemini/src/adapter.rs::base64_encode`, hand-rolled to avoid a crate dependency) and the uuid used for staged filenames come along; both are pure and wasm-safe (`aether_data` already carries `Uuid`).

### 3. I/O becomes mail

Each I/O site in the native runtime halves maps to a mail dispatch:

- **Messages API and Gemini HTTPS** → `aether.http.fetch`. The guest builds the request body with the ported pure function, constructs the `Fetch` (method, URL, headers — including the `x-api-key` / auth header from its init-config, §5 — and the encoded body), and mails it to `aether.http`. The `FetchResult` reply carries status, headers, and body bytes, which the guest feeds to the ported parser. The client-side per-sender bound is ADR-0158's; the guest sends and awaits, holding no queue of its own (§4). The transport's blocking `ureq` agent (`aether-contentgen/src/transport.rs`) has no guest analog and retires with the native halves.
- **The `claude` CLI backend** → `aether.process.run`. `aether.anthropic.cli.send` builds the CLI invocation and mails a `run` with `binary: "claude"`, an argv array, the request piped as `stdin`, and a timeout; the reply's `stdout` feeds the same text-extraction path. ADR-0157's allowlist must admit `claude` for the component to use this backend; an allowlist that omits it yields the graceful `CliNotFound`-shaped skip the kind already models. No API key rides this path.
- **Gemini artifact staging** → `aether.fs.write`. After parsing the generated bytes out of the `FetchResult` body, the guest mails `aether.fs.write { namespace: "save", path: "gen/<uuid>.{png,wav}", bytes }` and, on the write reply, replies to the original caller with the staged path. The staging root that chassis boot currently derives (`GeminiParams::gen_root`) moves into the component's init-config (§5). The atomic tmp-plus-rename write stays native, inside the `aether.fs` cap.
- **Gemini reference-image reads** → `aether.fs.read`. Nano Banana's `object_reference_paths` / `character_reference_paths` name files the native cap reads to bytes before dispatch (`runtime.rs::read_reference_images`). The guest reads each through `aether.fs.read` and base64-encodes it into the request body with the ported `base64_encode`, so a Nano Banana call with reference images fans one read per path before the fetch.

**Implementation gate — the 16 MB egress body cap.** A generated image or audio artifact arrives inside the `aether.http.fetch_result` response body, which the `aether.http` client bounds at `AETHER_HTTP_MAX_BODY_BYTES` (`DEFAULT_MAX_BODY_BYTES`, 16 MB). A 4K Nano Banana render or a long Lyria clip can exceed that, and the same bytes then ride mail from the http cap to the guest and from the guest to `aether.fs`, so the RPC frame budget (`AETHER_MAX_FRAME_SIZE`) applies too. The implementation must measure real multi-megabyte payloads against both bounds; raising the http body knob (and, if needed, the frame budget) is in scope for issue #3892 rather than a follow-up.

### 4. Two-handler state machine, no guest-side pending work

Each request/reply flow is the `send_with_context` / `take_context` two-handler shape (ADR-0139), the pattern `aether.kit.mesh` already runs:

- The request handler (`on_messages_send`, `on_generate`) builds the body, stashes a kind-typed context carrying the original caller's `ReplyHandle` and the request's `request_id`, mails the edge request `send_with_context`, and returns.
- The reply handler (`on_fetch_result`, and for gemini a further `on_write_result`) recovers the context with `take_context`, runs the pure parser, and replies the provider `_result` kind to the original caller.

Gemini's media flow chains a third leg — `fetch` reply, then `fs.write`, then the caller reply — each leg a fresh `send_with_context`. Because `send_with_context` inherits the handler's causal chain (ADR-0080), the whole chain stays open engine-side until the final reply settles; the guest carries only small bookkeeping contexts between legs.

**The guest never queues pending work guest-side.** A guest context holds nothing open engine-side — ADR-0139 §4 records that its blast radius is the actor's own heap, with no settlement hold — and the guest FFI for `dispatch_blocking` is deferred (ADR-0093 §7). A guest that buffered over-budget requests in its own memory would let the causal chain settle while work still sat in that buffer: `send_mail_traced` would observe the chain settled before the buffered reply ever dispatched (the premature-settlement window). Bounding at the http edge instead (ADR-0158) keeps queued requests engine-side under the cap's `SettlementHold`, settlement-correct by construction. The guest issues each `aether.http.fetch` immediately and lets the edge decide whether it runs or queues.

### 5. API keys ride init-config bytes

Each component receives its secrets and tuning as ADR-0090 init-config bytes at load: the API key (`ANTHROPIC_API_KEY` / `GEMINI_API_KEY` value), the per-request timeout, model defaults, and — for gemini — the `gen_root` staging path that chassis boot used to derive. `load_component` / `spawn_substrate` thread these as the component's `Config` kind (the MCP `config_path` bytes path), and `init` reads them into the actor's state.

This puts the raw key inside the wasm component's memory and onto the `x-api-key` header of each `aether.http.fetch`. The owner has accepted this as the interim posture for this arc. **Secret-reference headers** — the component naming a key by handle and the native http edge resolving it against a substrate-held secret so the plaintext never enters guest memory — are the named future hardening, parked here rather than built. Recording the interim posture explicitly keeps the security boundary legible: the trust model is "the substrate owner trusted this component when they loaded it with this key," unchanged in spirit from ADR-0050 §6.

### 6. Provider capabilities leave default chassis composition

The companion refactor (issue #3893) drops `AnthropicCapability` / `GeminiCapability` — and the `GeminiParams` gen-root plumbing plus `ContentGenConfig` — from the chassis builder chain, the CLI roots, and the config registry. Provider access stops being a chassis-boot fixture and becomes opt-in: a substrate that wants it uploads and loads the `aether.anthropic` / `aether.gemini` component (boot manifest or `load_component`). The native runtime halves of `aether-anthropic` / `aether-gemini` and the `aether-contentgen` `ureq` transport plus staging retire once both components reach parity.

## Consequences

### Positive

- **Provider access composes like any other actor.** A workload loads the provider component it needs; a CI mesh-dispatch runner or a pure-rendering substrate carries none of the provider machinery at boot. The harness loads `aether.anthropic` and mails it the same kinds it mailed the native cap.
- **The pure/transport seam is now a crate boundary, not a feature flag.** The fixture-tested logic runs guest-side over the exact functions it tests; the socket, subprocess, and disk stay native behind three general edge capabilities that other components reuse.
- **One bounding story for guest egress.** Every guest that calls out over HTTPS inherits ADR-0158's per-sender edge bound; provider components need no bespoke concurrency machinery, and the settlement correctness is the edge's, not each guest's.
- **Edge capabilities earn reuse.** `aether.process.run` and the async `aether.http` are general — the provider components are their first guest consumers, not one-off plumbing.

### Negative

- **The plaintext key lives in guest memory.** The interim init-config posture (§5) trusts the loaded component with the raw key; secret-reference headers are parked, so a malicious or compromised provider component can read its own key. Acceptable for the current trust model, revisited when the hardening lands.
- **A media generation is a longer mail chain.** Gemini's fetch-then-write-then-reply chain replaces a single native handler that did both, so a generation crosses more mailboxes. The chain stays engine-held and settlement-correct, but it is more moving parts than the native cap.
- **Two large native crates retire and re-land as components.** Until both components reach parity (issues #3891, #3892), the arc carries the native and guest implementations side by side; the retirement is gated on parity, not scheduled.

### Neutral

- **Callers are unaffected.** Byte-identical wire kinds and the lineage-addressed mailbox mean a `send_mail` caller changes the recipient address from a chassis mailbox to a loaded-component address and nothing else. `describe_kinds` shows the same kinds.
- **Cost and usage telemetry are unchanged.** The `Usage` reply field and the per-actor log ring (ADR-0081) carry the same cost surface from a guest actor as from a native one.

## Alternatives considered

- **Keep the capabilities native (the status quo).** Every chassis keeps linking provider machinery it may never call, and provider logic stays unreachable from guest space. Rejected: the harness direction wants provider access as a loadable actor, and the pure fraction is already large and wasm-ready.
- **Guest owns the key and the I/O (the ADR-0050 rejection).** ADR-0050 weighed a guest that holds both the key and the socket/subprocess and rejected it on security and per-call round-trip latency. This ADR keeps the socket, subprocess, and disk native and moves only the pure logic guest-side, so that rejection does not reach the design here.
- **Guest-side worker pool / pending queue.** Give the guest its own concurrency primitive so it queues over-budget requests. Rejected on settlement correctness: a guest holds no engine-side hold (ADR-0139 §4) and has no `dispatch_blocking` FFI (ADR-0093 §7), so a guest queue reopens the premature-settlement window. The bound belongs at the http edge (ADR-0158).
- **New wire kinds for the guest components.** Reshape the kinds while moving them. Rejected: byte-identical kinds keep every caller unaffected and keep this ADR to a single concept (where the kinds are handled), leaving ADR-0050's vocabulary intact.

## Follow-up work

- **Implementation — anthropic** (issue #3891): the `aether.anthropic` component over `aether.http.fetch` (messages) and `aether.process.run` (CLI), pure logic ported, fixtures as guest-side unit tests plus a harness end-to-end against a stub. Blocked on this ADR merging and the ADR-0157 / ADR-0158 implementations.
- **Implementation — gemini** (issue #3892): the `aether.gemini` component over `aether.http.fetch` and `aether.fs.write` staging, with the 16 MB egress body cap measured against real 4K / long-clip payloads. Blocked on this ADR merging and the ADR-0158 implementation.
- **Chassis refactor** (issue #3893): remove the provider caps from default composition and retire the native runtime halves plus the `aether-contentgen` transport once both components reach parity.
- **Parked, future hardening**: secret-reference headers, so the plaintext key never enters guest memory (§5).
- **Parked, named non-goals**: egress token streaming (buffered replies match today's behavior); a guest-reachable `dispatch_blocking_p32` (ADR-0093 §7's deferred FFI superset — desirable, one system reusable for wasm and native, but not needed for this arc).
