# ADR-0194: The lane confines its harness child

- **Status:** Proposed
- **Date:** 2026-08-14

## Context

ADR-0150 draws the pipeline's trust boundary around credentials: workers never hold one, a worker cannot verify its own candidate, and the construct lane runs on the instance owner's own machine under their own ambient harness auth because subscription credentials are non-delegable. ADR-0152 draws the other half around writes: the child process never stages, commits, or pushes, because capture happens above it in the trust domain that already holds the token. Both boundaries are real, and neither is enforced by the operating system. What actually holds them today is the environment scrub (`scrub_coordinator_env` in `crates/aether-chassis-bloomery/src/bloomery/executor/local/lane_env.rs`, which removes every `AETHER_`-prefixed knob plus `GITHUB_TOKEN` from the child's environment) and the host-side capture path — a policy about what the child is *given*, with nothing standing between the child and the rest of the filesystem the operator's own user account can reach.

That gap widened when the headless write gate opened. `construct_argv` in `xtask/src/transform/claude.rs:38` passes `--dangerously-skip-permissions`, which is what makes the arm run at all: under the default permission mode a non-interactive `claude -p` denies every edit and the lane investigates for dozens of turns against a worktree it cannot change, which the fail-closed capture reads as `produced_candidate: false`. The flag is correct for the problem it solves and it removes the only in-process restraint that arm had. The Grok arm, added since, sits in the same place — `grok_argv` in `xtask/src/transform/grok.rs` passes `--permission-mode bypassPermissions` for exactly the same reason. Two of the four arms therefore fork a child whose write reach is the operator's entire home directory.

The other two arms keep a restraint of their own, though not the one the issue behind this decision recorded. `muse_argv` (`xtask/src/transform/muse/mod.rs:48`) passes `--disable-approval` and deliberately withholds `--yolo`, so Muse's own sandbox stays on. `codex_argv` (`xtask/src/transform/codex.rs:41`) passes `--approve-for-me` **alone** and must not name a sandbox alongside it: `--approve-for-me` already implies the workspace-write sandbox, and codex-cli refuses to start when `--sandbox` is also given, so the tripwire at `xtask/src/transform/codex.rs:189` asserts the absence of `-s` / `--sandbox` rather than their presence. Whatever confinement the pipeline adds has to compose with those two sandboxes rather than replace them, because neither is ours to configure and both are load-bearing for their arm.

The layout the confinement has to describe is not a single directory. `ProcessTransformRunner::start` (`crates/aether-chassis-bloomery/src/bloomery/executor/local/process_runner.rs:128`) resolves three sibling paths under the coordinator's scratch base (`CoordinatorConfig::local_worktree_base`, default `.bloomery/local-worktrees`): the lane slot's canonical checkout `slot-<index>`, its cargo target directory `slot-<index>-target`, and the dispatch's nonce-keyed evidence directory `<nonce>-evidence` that arrives on the child's argv as `--out`. The checkout is a persistent per-slot path rather than a fresh directory per run, because `sccache` keys compilations partly by the paths cargo names, so a dispatch that builds where an earlier one built inherits what it compiled; `materialize_checkout` resets that path in place and falls back to `git worktree add --force --detach` only when the reset fails. The lane adds a fourth: `Scratch::prepare` (`xtask/src/transform/scratch.rs:32`) creates a per-run directory under the host's `AETHER_LANE_SCRATCH` root, or under the evidence directory when the host named none, and exports it so the child builds its throwaway target trees somewhere the run can reap.

Two facts about that layout matter for any path policy. The scratch base ships as a relative path, so on a default deployment the lane slots sit *inside* the operator's own repository checkout, which makes "deny the operator's checkout, allow the worktree" a statement about nesting rather than about two disjoint trees. And a linked worktree keeps no repository of its own: its `.git` is a file pointing at `<clone>/.git/worktrees/slot-<index>/`, where its index, `HEAD`, and per-worktree refs live, while objects, config, and packed refs are read from the parent clone's common directory. A child that can read and write nothing under the parent clone cannot run `git status` in its own checkout.

The alternative shape of guard — an approval classifier reading the lane's diff and deciding whether to allow it — is the wrong instrument here for reasons that are about measurement as much as safety, and they are recorded under Alternatives.

## Decision

The transform process confines itself before it forks a harness child, so every arm runs under one kernel-enforced floor regardless of what restraint its own CLI applies.

1. **The policy is an allow list over path hierarchies, and everything outside it is denied by construction.** Read-write for the dispatch's slot checkout, the slot's cargo target directory, the run's `AETHER_LANE_SCRATCH` directory, the evidence directory the child writes `evidence.json` into, and the system temporary directory. Read-only for the toolchain roots the child needs to compile (the resolved `CARGO_HOME` and `RUSTUP_TOOLCHAIN` locations, and the executable search path) and for the harness CLI's own configuration and authentication state, which the child legitimately holds — ADR-0150 puts the construct lane under ambient auth by design, so that one credential stays reachable and read-only rather than being pretended away. Nothing else is granted, which is how the coordinator's `SQLite` store, the artifacts root, and the operator's working checkout become unreachable: not by naming them in a deny rule, but by never appearing in the allow list. Every granted path is resolved from the dispatch's own inputs at confinement time; none is a literal in the source.

2. **The mechanism is Landlock, self-applied.** The ruleset is built and enforced inside `cargo xtask transform` at `run_model_lane` (`xtask/src/transform/mod.rs:261`) — the single seam every arm passes through, and the last point before `claude::run_headless_claude`, `codex::run`, `muse::run`, or `grok::run` forks its CLI. Landlock needs no privilege, no external wrapper binary, and no coordinator-side configuration, so one implementation covers all four arms and the coordinator gains no new knob that can drift out of agreement with the lane. It restricts the calling thread and is inherited by every process that thread forks, and it cannot be relaxed once applied, so a child cannot undo it and neither can a grandchild. It composes with, rather than replaces, the Codex and Muse sandboxes: those two arms end up with their own restriction and the kernel's, and the intersection is what runs.

3. **Lanes keep worktrees, and the gitdir is derived rather than enumerated by hand.** The two paths git needs are grants like any other, split by what the child is allowed to do with each: read-write on the worktree's own administrative directory under `<clone>/.git/worktrees/slot-<index>/`, so `git status` and `git diff` can refresh an index; read-only on the clone's common directory, so objects, config, and packed refs resolve. Both paths are asked of git from inside the checkout at confinement time rather than being assembled from string fragments, which is what keeps the rule from being fragile — the layout's own authority reports it, so a future change in how git arranges linked worktrees moves the grant with it. The read-only common directory also turns ADR-0152's boundary from a convention into an enforced property: a child that cannot write loose objects cannot create the capture commit the host exists to create.

4. **The ABI floor is stated, and a host below it degrades rather than failing.** Landlock's available restrictions are versioned, and the version a host offers depends on its kernel: filesystem access rights arrived with ABI 1 (Linux 5.13), cross-hierarchy `refer` with ABI 2 (5.19), `truncate` with ABI 3 (6.2), and TCP bind and connect rules with ABI 4 (6.7). ABI 1 is the minimum at which this policy means anything, because the whole filesystem allow list is expressible there. ABI 3 is the floor at which a read-only grant is honestly read-only, since a host without the `truncate` right can still let a confined process empty a file it is allowed to open. The ruleset is therefore requested best-effort against the running kernel: the process asks for the rights this policy needs, accepts the subset the host supports, and records which of the three outcomes it got — fully enforced, partially enforced, or not enforced at all. A partial enforcement is a real restriction and runs; it is not silently reported as a full one.

5. **A host without Landlock runs unconfined and says so in the evidence.** Development happens on macOS boxes, which have no Landlock and would need a second, differently-shaped implementation to be confined at all. Refusing to dispatch there, or gating on a configuration flag, makes confinement a reason a bloom cannot run on the machine the pipeline is developed on — and an operator who hits that will set the escape flag once and leave it set, which converts a legible per-dispatch fact into a permanent invisible one. So the lane runs, and the enforcement outcome is stamped onto the run's evidence beside the readings that are already stamped there — `Evidence::measured_by` and `Measurements::stamp` in `xtask/src/transform/mod.rs` already carry the `sccache` counters and the peak resident set this way, each presence-driven. A dispatch whose evidence says it ran unconfined is a fact an auditor can count; a dispatch that merely differed from its sibling on another host is not.

6. **Network stays open, and that is a named gap rather than an omission.** All four arms are API clients whose entire purpose is to reach a model endpoint, so a network restriction that is worth applying would have to distinguish the model API from everything else. Landlock's network rules cover TCP bind and connect only, and connecting to an HTTPS endpoint is precisely what the lane must do, so nothing at that layer separates the traffic the lane needs from the traffic it should not make. Confinement in this decision is filesystem confinement. A child that wants to exfiltrate what it can read still can, and the mitigation for that remains the environment scrub keeping credentials out of its reach.

7. **The acceptance bar is a mutation matrix, not a happy path.** A confinement that is only ever exercised by runs which stay in policy proves that the pipeline still works, which is the property that would hold with no confinement at all. What has to be demonstrated is that a real out-of-policy write from a real forked child fails, and that the in-policy path is unaffected — a candidate written into the slot checkout still captures and still becomes a `CandidateRef` the way ADR-0152 describes. Both halves are required, and the failing half is the one that carries the evidence: a guard never run against a violation is an assertion about the guard's source code, not a measurement of the guard.

## Consequences

- The claude and grok arms stop being the least-confined of the four. Their CLI-level write gates remain wide open, which is what makes them run headless, and the reach behind those gates narrows to the paths the dispatch actually owns.
- The trust boundary ADR-0150 and ADR-0152 describe becomes checkable rather than only stated. "The child never commits" and "the coordinator's store is not the lane's to touch" acquire an enforcement mechanism that does not depend on the agent's cooperation, its prompt, or the reviewer's reading of a diff.
- A lane workpiece that edits the harness arms themselves — routine work in this repository — is no longer a special case for the guard, because the confinement judges the process rather than the change. This is the property the classifier alternative cannot have.
- Confinement is filesystem-only and Linux-only. Two arms carry their vendor sandbox and the kernel's; two carry only the kernel's; macOS hosts carry neither and stamp that fact. The pipeline therefore has three enforcement postures rather than one, and the evidence record is what keeps them distinguishable when a calibration cell is read back.
- Costs, accepted: a new dependency on the `landlock` crate in the transform tool's manifest, which is a separate authorization tier from the code that uses it and lands on its own; a path policy that has to be updated whenever the dispatch grows a directory the child legitimately writes, with the failure mode being a lane that cannot build rather than one that escapes; and the diagnostic burden of a denied write surfacing to the agent as an ordinary permission error, which a model may spend turns trying to route around before concluding it cannot.
- The lane-boundary harness (`crates/aether-chassis-bloomery/tests/lane_boundary.rs`) substitutes the program at the end of the argv through `AETHER_BLOOMERY_LANE_PROGRAM`, so its scenarios run the mock lane rather than `cargo xtask transform`. The capture half of the proof has to account for that substitution honestly — either the substituted program applies the same policy, or the scenario that proves capture survives confinement runs against the real transform entrypoint. A scenario that exercises a mock lane which was never confined proves nothing about confinement.
- Follow-on work this opens: the verify lane, which runs the same entrypoint but is mechanical, zero-secret, and executes on shared runners whose layout differs from a local slot, is deliberately outside this decision and is a separate question; so is a second implementation for macOS, should the posture in point 5 stop being acceptable.

## Alternatives considered

- **An approval classifier inside the lane** — a model judging each proposed write and allowing or refusing it. Rejected on three counts. A false positive does not degrade a run, it burns one: the lane's repair budget is finite (ADR-0180), and a refused legitimate write costs a whole roll. A probabilistic gate in the execution path adds nondeterministic variance to every calibration cell, and ADR-0184 measures calibration from the journal on the premise that a cell's spread comes from the model under test rather than from a second model in the loop. And a classifier reads what a diff says while the property at issue is what a process does, which is exactly backwards for a repository whose lane workpieces routinely edit the harness arms — a diff touching `xtask/src/transform/claude.rs` is normal work here and indistinguishable, textually, from tampering.
- **Detached clones per lane slot instead of worktrees.** Rejected. It removes the gitdir grant from the policy and replaces it with a per-slot object database: the workspace's history duplicated for every slot the concurrency ceiling allows, and a per-slot fetch on the dispatch path where the shared object database currently satisfies `fetch_subject_if_absent` once for all slots. The disk cost is bounded and the latency cost is a fetch, so neither is disqualifying on its own — what decides it is that a full clone hands the child a writable object database of its own, so "the child never commits" stops being enforced by the confinement and reverts to convention. A clone with alternates pointing back at the parent avoids the duplication and reintroduces the same read grant, buying nothing.
- **An external wrapper binary — `bwrap`, a container, a systemd scope.** Rejected as the v1 mechanism: it adds a host dependency the lane must detect and a second place the policy is written, and the coordinator would have to know how to invoke it, which is the configuration drift self-confinement avoids. It remains the natural answer if mount namespacing or network scoping is ever needed, and it composes with this decision rather than contradicting it.
- **Confining at `cargo xtask transform`'s entry rather than at `run_model_lane`.** Rejected for v1 because the same entrypoint serves the mechanical verify lane on shared runners, where the layout this policy describes does not exist; a policy resolved against a lane slot that is not there would deny the runner's own workspace and fail every verify job. The narrower seam is where the agent is, which is where the decision is about.
- **Running the lane as a separate operating-system user.** Rejected: it confines by ownership, which is coarser than the policy needs (the operator's checkout and the lane's slot are the same user's files, frequently the same tree), and it collides with ADR-0150's ambient-credential design, since the harness CLI's auth state lives in the operator's own account.
- **Status quo — environment scrub plus the host-side capture path.** Rejected: it is a policy about what the child is handed, and it says nothing about what the child can reach. The scrub is still necessary and stays; it was never sufficient, and the two arms running with their write gates open are where the insufficiency became concrete.
