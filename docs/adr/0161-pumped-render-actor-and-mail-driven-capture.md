# ADR-0161: Pumped Render Actor and Mail-Driven Capture

- **Status:** Proposed
- **Date:** 2026-07-22

## Context

ADR-0160 introduced the pumped dispatch home and migrated the window bolt-on onto it; that arc has landed (`PumpedSlot`, `boot_pumped_actor`, the desktop window actor) and named the render migration as the follow-on it unblocks. This ADR decides that migration.

`RenderCapability` dispatches correctly on the worker pool — its cost rows, trace hops, and registration are all sound. What it pays for pooled dispatch is a shared-state seam with the driver thread, because frame recording and present must run on the main thread with the surface: `RenderHandles` carries nine `Arc`'d accumulator fields with documented lock orderings and a module-level `significant_drop_tightening` allowance guarding a TOCTOU window; `gpu: Arc<OnceLock<RenderGpu>>` is late-installed from the driver's `resumed`; and `CaptureBackend` is a cross-thread readback queue whose entries carry retained reply guards, with a smuggled `HubOutbound` for its inline-failure replies. The harness has its own arm of the seam (`RenderExt::install_capture_backend`, post-boot GPU install), and the whole bundle crosses threads through the `publish_handle` / `ExportedHandles` handshake.

Pumping the render actor on the driver thread collapses every one of those into plain state fields on a same-thread actor. Render could not reuse the window's pump point, and that constraint shapes this design: draw mail is emitted mid-frame as descendants of the `LifecycleAdvance` broadcast chain, and the driver blocks in `await_internal_signal` waiting for that chain to settle — settlement requires the render handlers to have dispatched, so a render slot pumped only at `about_to_wait` deadlocks the advance loop. The same trap recurs inside capture: `on_capture_frame`'s pre-mails routinely start chains that terminate back at the render mailbox itself (a pre-mail pokes a camera component, which publishes `aether.view_projection` to render — the issue 860 scenario), so no render handler can ever block waiting on a pre-mail settlement; only a pump-capable site can.

Two supporting facts, verified: wgpu statically asserts `Surface<'_>: Send + Sync` on native, so a state owning the surface, device, and queue satisfies `NativeActor::State: Send + 'static` unchanged; and live `describe_handlers` on a desktop substrate shows `aether.render.create_texture` reported twice with differing reply declarations — the two linked render runtimes have drifted on a declared contract, a small standing cost of the current split this migration's cleanup pays off.

## Decision

`RenderCapability` becomes a pumped actor on the chassis driver thread, its state owning the accumulators, the GPU, and the pending capture outright. Four settled design choices, then the slicing.

**1. The driver requests frames by mail.** A chassis-internal kind `aether.render.frame { replay_cache_when_idle }`, mailed by the driver each `RedrawRequested` after the advance chain settles and dispatched through the pumped slot. Frame recording becomes a handler: it gets `Received` / `Finished` trace brackets and a cost row, so `actor_cost aether.render` reports actual frame-record time. `replay_cache_when_idle` carries the issue 847 semantic (harness captures replay the last committed accumulators when the producer was idle; desktop always commits current). `PumpedSlot` keeps read-only state accessors for the driver's loop decisions; everything mutating goes through mail.

**2. The settlement wait pumps on a unified wake channel.** One internal channel of `enum PumpWake { Settled, Mail }`: the render slot's wake sends `Mail`, and settlement subscriptions send `Settled` through an additive callback-form `subscribe_settlement` on the settlement registry (std `mpsc` cannot select, so the two producers share one channel). `await_settlement_pumped` drains the slot on each `Mail` wake and keeps `await_internal_signal`'s escalating-patience bookkeeping. Per-round pumping is rejected: the round budget is a log cadence, and settlement is gated on the very mail that would sit waiting out the round.

**3. The GPU co-locates in `aether-render` with lazy boot.** Today's desktop `Gpu` body (instance, surface, adapter, device, swapchain config, blit-and-present, the wireframe overlay pipeline) moves into aether-render's pumped runtime behind a `desktop` feature, mirroring ADR-0160's aether-window shape. `RenderParams` gains the same `WindowCell` the window actor receives — one cell, cloned into both params — plus the wireframe config value; the first `on_frame` after `resumed` finds the cell filled and boots wgpu via `get_or_insert_with`, a one-time cost that lands visibly in the first cost sample. The alternative split (actor records offscreen, chassis blits and presents) is rejected because the blit needs the offscreen texture across the boundary — `RenderHandles` reborn in miniature.

**4. Capture is a mail-driven state machine inside the actor.** Two more chassis-internal kinds complete it:

- `aether.render.pre_settled { mail_id }` — `on_capture_frame` bridges each pre-mail settlement to mail via the decision-2 callback subscribe, pushed from whatever thread the settlement fires on.
- `aether.render.occluded { occluded }` — the driver forwards `WindowEvent::Occluded`; the handler fail-fasts a pending capture (relocating `fail_capture_if_occluded` into the actor), and `on_capture_frame` replies `Err` inline when already occluded, preserving the issue 1317 fail-fast at the source.

`PendingCapture` becomes plain state — `{ reply: InboundMail, after_mails, checks, reference, pre_remaining: usize, deadline: Instant }` — no `Arc`, no atomic, no cross-thread queue, no wake call (arriving as mail already fired the slot's wake). `on_frame` decides per frame: `pre_remaining == 0` → record with capture copy, read back, reply through the retained guard; past `deadline` → reply `Err`, reproducing the `FRAME_SETTLEMENT_CAP` wedge-to-`Err` semantics event-driven; otherwise record plainly and the capture rides a later frame. The loop-turning rule generalizes what the window actor established: a pumped slot's wake pokes a redraw — `UserEvent::Capture` is deleted, not relocated. The one hole and its honest patch: a parked, non-occluded window with a wedged pre-chain generates no wakes, so nothing reaches the deadline check — the driver reads `capture_deadline()` after each drain and sets `ControlFlow::WaitUntil(deadline)`. That single read is the only capture-awareness the driver retains; `RedrawRequested` collapses to advance loop → frame mail → drain.

**Slicing.** Five slices, staged so the pooled and pumped render runtimes coexist until every consumer has swapped: (R1) `aether-substrate` — the callback-form `subscribe_settlement`, the `PumpWake` channel, `await_settlement_pumped`, and the read-only accessor surface on `PumpedSlot`; (R2) `aether-render` — the pumped runtime added beside the pooled one: owned-field state, the three internal kinds and their handlers, the moved desktop GPU body behind the `desktop` feature; (R3) `aether-chassis-desktop` — the driver swap, deleting `render.rs`, `fail_capture_if_occluded`, `UserEvent::Capture`, and the capture branch, gated on the dispatch-perf comparison plus an aether-harness-perf before/after; (R4) `aether-harness-substrate` — the second pumping driver, its capture crate passing an offscreen-only GPU config through params instead of installing post-boot, and the concrete case of ADR-0160's "a pumped driver whose loop starts parked must drain once at pump start"; (R5) the deletion slice — `RenderHandles`, `CaptureBackend`, `install_gpu`, the `publish_handle` handshake, `RenderExt::install_capture_backend`, `commit_or_replay`, the lock-ordering docs and lint allowance, and the stale `adapter_info` retention whose `platform_info` reader died in issue 603; `triangles_rendered`'s shutdown log moves into `unwire`, and the headless runtime's `create_texture` reply declaration is aligned so `aether.render` reports a single deduped row set.

`HeadlessRenderCapability` stays pooled — no GPU, no seam to collapse.

## Consequences

- The largest shared-state seam in the codebase is deleted rather than managed: no lock orderings, no TOCTOU allowances, no capacity-mirroring subtleties, no cross-thread capture queue, no install handshakes. `commit_or_replay`'s dual-lock swap becomes a bare `mem::swap` on owned fields.
- Capture behavior becomes fully determined by the actor's mail history: parked captures, readiness, and occlusion fail-fasts are traceable in `actor_logs` and traces, and every transition is a handler testable headlessly with a toy pump. The cost is capture completing on the first frame after readiness instead of within the same redraw — one frame of latency on an observation path whose consumer is an MCP call measured in hundreds of milliseconds.
- Frame recording gains a cost row and trace brackets — the single most useful cost number the engine did not have. The first sample includes the lazy wgpu boot, which is honest and visible rather than hidden in chassis code.
- Draw dispatch moves onto the main thread. It was already on the frame's critical path — the advance chain cannot settle before render handlers dispatch — and the per-handler mutex traffic disappears, so the expectation is neutral-to-better; the R3 gate verifies rather than asserts (the `Compare dispatch perf vs merge-base` CI job plus aether-harness-perf before/after).
- A second pumping driver (the harness) exercises the primitive off winit, including the drain-at-pump-start rule ADR-0160 recorded.
- `aether-render` gains a feature-gated winit + surface edge, mirroring aether-window's; default features unchanged, headless consumers pay nothing.
- The `WaitUntil(capture_deadline)` read is a deliberate, bounded exception to "the driver knows nothing about capture" — it knows a deadline exists, never what capture logic to run. Removing even that would require timer machinery inside the actor model that nothing else needs.
- During R2–R4 the crate briefly carries two GPU-capable runtimes; the staging exists so desktop and harness swap independently and every intermediate commit ships green. R5 ends the coexistence.

## Alternatives considered

- **Driver-orchestrated capture (the driver blocks on pre-settlements, then mails the frame).** Preserves today's same-redraw capture latency, but keeps the ready-check, the blocking wait, the wedge disposition, and the occlusion branch in the driver — the mechanism seam is deleted while the logic seam survives, and the pre-settlement receivers (or a countdown atomic) still cross the actor boundary. Rejected: one frame of capture latency is the cheaper price.
- **Per-round pumping inside `await_internal_signal`.** Rejected: draw mail would wait out a log-cadence round while settlement is gated on it — added frame time by construction.
- **Actor records offscreen; chassis keeps surface and present.** Rejected: the blit needs the offscreen texture across the boundary, recreating the shared-handle seam this ADR deletes.
- **`PumpedSlot::with_state` mutation instead of frame mail.** Sound (same thread, `&mut` access) but keeps frame recording outside dispatch — no trace brackets, no cost row — and preserves a chassis-reaches-into-cap-state edge. Rejected; read-only accessors remain.
- **Migrating render inside the ADR-0160 arc.** Already rejected there for sequencing; the window swap proved the primitive on a low-frequency mailbox before this arc adds the settlement-wait pump, the frame-invocation surface, and harness pumping.
