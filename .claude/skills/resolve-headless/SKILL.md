# /resolve-headless — headless conflict-resolution wrapper

This wraps `/resolve` for a headless agent running one-shot on an ephemeral GitHub Actions runner. It carries no process of its own. `/land` dispatches it on a `dirty` PR (`gh workflow run agent-work.yml -f task=resolve -f ref=<pr>`).

Execute `../resolve/SKILL.md` verbatim — the preconditions, the merge-`origin/main`-into-the-branch mechanic, the conflict resolution (semantic ones included), the merge commit and non-force push, the CI Refine loop, the review re-request, the terminal hand-back to the held→land path. Where the original touches the interaction surface, `../headless/protocol.md` governs. An instruction is overridden if and only if it appears in the Overrides table below, cited by the original's anchor; everything else is the original's, unchanged. An improvement to `/resolve` is live here the moment it merges, because this wrapper only references it.

Before any process step, run the protocol's [re-entrancy-first](../headless/protocol.md#re-entrancy-first) guard: check whether the PR is already merged (nothing to resolve), whether its `mergeable_state` is still `dirty` (a prior resolve may have already pushed a resolution — if it is no longer `dirty`, the conflict is gone and the job is a clean no-op), whether the branch already carries an unpushed resolution, and whether an unanswered `agent:awaiting-answer` park is open on the PR, then post a start-of-work comment with the run link and begin the original at the phase the observed state implies.

## Overrides

| Original anchor | Interactive behavior | Headless override |
|-----------------|---------------------|-------------------|
| [`## Resolution procedure`](../resolve/SKILL.md#resolution-procedure) step 1 checkout | `git checkout "$branch"` in the current working tree | [checkout-as-isolation](../headless/protocol.md#checkout-as-isolation) — the runner's `$GITHUB_WORKSPACE` checkout is the workspace; check the PR's head branch out directly in it, no worktree add. The re-entrancy guard derives prior-attempt state (already merged, no longer dirty, an unpushed resolution) from GitHub and the checkout rather than from a stale on-disk worktree |
| [`## Resolution procedure`](../resolve/SKILL.md#resolution-procedure) step 4 commit | Commit the merge in the current git identity | [commit-identity-assert](../headless/protocol.md#commit-identity-assert) — assert the owner's public `user.name` / `user.email` before committing; never author the merge commit or a Refine-loop fix under the owner's real name or personal email |
| [`## Self-bounce mechanics`](../resolve/SKILL.md#self-bounce-mechanics) incompatible-intent surface | Abort the merge, surface the incompatibility with the conflicting files and the two intents in tension, and stop for the person | [ask-and-park](../headless/protocol.md#ask-and-park) — after `git merge --abort`, post the same content in the park shape, apply `agent:awaiting-answer` + `agent:park:resolve`, exit 0. The budget-breach self-bounce (retry cap / wall clock) parks the same way with the attempt history |
| [`## Terminal state`](../resolve/SKILL.md#terminal-state) "Print to user" and the hand-back | Print the resolved-head summary and hand back to the held→land path | [end-turn-not-wait](../headless/protocol.md#end-turn-not-wait) — leave the resolved head green with the review re-requested (the reconciler computes its resting state — `phase:held`, or `phase:findings` when the fresh verdict is actionable), post the terminal state as a comment, end the turn; the held→land path resumes it elsewhere |

Everything the table does not cite — the preconditions, the merge-in and conflict resolution, the commit-and-format discipline, the non-force push, the CI classification and flake handling, the review re-request, the declared-surface containment — is `/resolve`'s, verbatim.

**Not overridden — the Refine loop's CI wait.** [`## Refine loop`](../resolve/SKILL.md#refine-loop-spin-the-resolved-head-green)'s `scripts/wave-status.sh --wait <pr>` poll is an in-job wait on CI, not on a human, so [end-turn-not-wait](../headless/protocol.md#end-turn-not-wait) does not override the wait itself — but a one-shot runner cannot block a foreground on it, so the agent realizes it the headless way the protocol's [CI-wait contract](../headless/protocol.md#the-ci-wait-contract) specifies: poll it mechanically with cheap in-turn status-check turns until CI settles, then continue the loop in the same box — never ending the turn on a pending background wait, and — while the wait is unsettled — never `ScheduleWakeup stop` or sign off as if the turn were done, either of which releases the process and abandons the loop before CI settles.
