# /approve-sweep-headless — headless batched approval wrapper

This wraps `/approve`'s [`## Sweep approve`](../approve/SKILL.md#sweep-approve) mode for a headless agent running one-shot on an ephemeral GitHub Actions runner. It carries no process of its own. One dispatch (`task=approve-sweep`, ref constant `all`) processes the whole approve queue: every eligible `phase:plan` issue, each through the full single-issue gate set, in one session — so a wave spends one runner on approval instead of one per issue.

Execute [`## Sweep approve`](../approve/SKILL.md#sweep-approve) verbatim — the REST enumeration, the full per-issue gate checks (freshness, dependency, umbrella integrity, ADR merge, model label), the drop-with-reason accounting, and the per-issue `phase:ready` reconcile — with `../approve/SKILL.md`'s single-issue sections governing each candidate exactly as they govern a single `/approve <n>`. Where the original touches the interaction surface, `../headless/protocol.md` governs. An instruction is overridden if and only if it appears in the Overrides table below, cited by the original's anchor; everything else is the original's, unchanged.

Before any process step, run the protocol's [re-entrancy-first](../headless/protocol.md#re-entrancy-first) guard, adapted to the batch shape: there is no single ref whose label answers "already done", so re-derivation IS the enumeration — a crashed sweep's approved issues rest at `phase:ready` and drop out of the next enumeration; the remainder rest at `phase:plan` and are simply processed again. An empty eligible set is a clean no-op: log it and end the turn. Post no start-of-work comment — the live run is the claim on the whole queue, and per-issue comments appear only where the sweep acts on an issue.

## The authority bound

Identical to [`/approve-headless`'s](../approve-headless/SKILL.md#the-authority-bound), enforced **per issue inside the batch**: this run advances only an issue whose tier resolves to `auto` — by the policy lookup or by an owner-applied `approval:pre-approved` (timeline-actor-verified, per [`### The owner's override`](../approve/SKILL.md#the-owners-override--approvalpre-approved)). Run [`## ADR hard gate`](../approve/SKILL.md#adr-hard-gate) and [`## Approval tier`](../approve/SKILL.md#approval-tier) for each candidate exactly as the original specifies; a `judge`, `human`, ADR-bearing, missing-surface, or unresolvable-tier issue is skipped with a log line and left resting at `phase:plan` for its reader. The dispatcher pre-filters so a sweep is not dispatched when nothing can advance, but the workflow is dispatchable by anything holding `actions: write`, so the bound is enforced here, at the point of each write, rather than trusting the caller.

## Per-issue isolation

One issue's failure never aborts the batch. Every candidate gets an independent outcome — advanced, skipped (non-auto tier / `agent:dont-touch` / `agent:awaiting-answer`), or parked (gate failure) — and the sweep continues to the next candidate. A candidate that throws mid-check (an API error, a malformed body) is recorded as parked-equivalent with the error in its park comment, never silently dropped.

## Overrides

| Original anchor | Interactive behavior | Headless override |
|-----------------|---------------------|-------------------|
| [`## Sweep approve`](../approve/SKILL.md#sweep-approve) step 1 enumeration | Enumerate every open `phase:plan` issue | Same REST enumeration, minus two exclusions enforced at the point of spend: an issue labeled `agent:dont-touch` (benched by the owner — the tick filters it too, but a control enforced in exactly one workflow is escaped by every other dispatch path) and an issue labeled `agent:awaiting-answer` (parked mid-question; its resume path is its own per-issue dispatch, never a batch) |
| [`## Sweep approve`](../approve/SKILL.md#sweep-approve) step 3 "print the approve plan and wait for confirmation" | Hold the whole batch behind one operator confirmation | Split by tier. For the **auto set**: dispatch-as-authorization — the tick's pre-filter plus [the authority bound](#the-authority-bound) above are the confirmation (a headless sweep only ever auto-advances what the policy or the owner's own label already cleared), so print the plan — advanced / skipped-with-tier / parked-with-reason — to the run log and `$GITHUB_STEP_SUMMARY` and proceed without waiting. For the **non-auto remainder**: the confirmation is displaced onto GitHub as [the verdict digest](#the-verdict-digest) — the same plan table, posted as a machine-filed issue the owner answers with one reply |
| [`## Sweep approve`](../approve/SKILL.md#sweep-approve) step 2 drop-with-reason (a candidate failing the [gate checks](../approve/SKILL.md#gate-checks), the [freshness gate](../approve/SKILL.md#freshness-gate), or the [dependency gate](../approve/SKILL.md#dependency-gate)) | Drop the issue from the batch and list the reason in the plan for the operator | [ask-and-park](../headless/protocol.md#ask-and-park) **scoped to that one issue**: post the full failure list in the park shape on that issue, apply `agent:awaiting-answer` to it, and continue the batch. The park marker names `task=approve ref=<n>` and carries **no `session=` pointer** — gate-check context is cheap to re-derive, so the owner's reply re-dispatches the single-issue `approve` task fresh rather than resuming a session that also processed the rest of the batch |
| [`## Approval tier`](../approve/SKILL.md#approval-tier) `judge` / `human` routing, and [`## ADR hard gate`](../approve/SKILL.md#adr-hard-gate) | The owner or judge reads the issue | [end-turn-not-wait](../headless/protocol.md#end-turn-not-wait) per issue — never auto-advance it, post no comment on the issue itself (a deliberate divergence from `/approve-headless`, which comments the resolved tier on its one dispatched issue: a sweep re-visits the whole plan board every wave, so a per-visit comment would repost the same verdict on the same resting issues tick after tick). The issue's owner touchpoint is its row in [the verdict digest](#the-verdict-digest); the run summary carries the tier lines |
| [`## Actions on pass`](../approve/SKILL.md#actions-on-pass) step 3 "Print a summary to the user" | Print the `✓ #N approved` summary to the operator's terminal | [end-turn-not-wait](../headless/protocol.md#end-turn-not-wait) — post the summary as a comment on each advanced issue (the same per-issue record `/approve-headless` leaves), and end the turn after the batch completes; dispatch nothing |
| [`## Freshness gate`](../approve/SKILL.md#freshness-gate) Tier A `git fetch origin main` and the `git log`/`git cat-file` reads | Run against the operator's local clone | [checkout-as-isolation](../headless/protocol.md#checkout-as-isolation) — the runner's `$GITHUB_WORKSPACE` checkout is the clone, on the default branch with full history; run the gate unchanged, once per candidate. Cut no branch and no worktree; `/approve` writes no code |

## The verdict digest

The non-auto remainder's one owner touchpoint (#3190): the interactive sweep holds its batch behind a terminal confirmation, and headless that confirmation becomes one machine-filed issue the owner answers with one reply — from GitHub or straight from the notification email (reply-by-email posts back onto the thread, which is what re-dispatches this sweep). Every branch below is re-derived from board state; no branch needs a stored session.

After the auto lane completes, run the digest lane in this order:

1. **Read an answered digest.** Enumerate open `agent:digest` issues (`gh api 'repos/iamacoffeepot/aether/issues?labels=agent:digest&state=open'` — REST, like every other read here). For a digest whose newest comment is authored by the repo owner and postdates the digest's own marker comment, that comment is the verdict. Authenticate by comment author — the same trust boundary the `approval:pre-approved` timeline-actor check encodes: only the owner's word waives a tier. Interpret the reply — free-form is expected ("approve all", "approve #3191 and #3195, hold the rest", "dismiss") — and **echo the interpretation** in the outcome comment so a misreading is visible and correctable rather than silent. The approvable set is the intersection of: issues listed in *that digest's* table, still open at `phase:plan` and still eligible on re-enumeration, and not ADR-bearing. For each, run the full single-issue [gate checks](../approve/SKILL.md#gate-checks) — the owner's verdict waives the **tier** (exactly the `approval:pre-approved` semantics: who approves, never whether the issue is approvable) — then apply [Actions on pass](../approve/SKILL.md#actions-on-pass). Post one outcome comment on the digest (approved / no-longer-eligible / held-by-your-reply, plus the echoed interpretation) and **close the digest issue** — closed is its terminal state. A "dismiss"-shaped reply closes it with no approvals. An ambiguous reply re-asks on the digest issue, re-applies `agent:awaiting-answer`, and ends the turn — never guess an approval.
2. **Leave an unanswered digest alone.** An open digest with no owner reply is still parked: log it, file nothing new — one open digest at a time; the tick's nudge machinery re-pings it on `AGENT_NUDGE_DAYS` — and end the digest lane.
3. **File a new digest.** No open digest, and the non-auto remainder is non-empty — plan issues whose tier resolved `judge` / `human` / ADR-bearing / no-surface, excluding `agent:dont-touch` and issues already parked on their own question (a parked issue has a pending owner interaction of its own and resumes per issue). File **one** new issue: labels `agent:digest` + `agent:awaiting-answer`, deliberately **no `type:*` label** (that absence plus the digest label keeps the tick's scope arm away — the `alert` invisibility contract). The body carries, in order: the park marker `<!-- aether-agent:awaiting-answer task=approve-sweep ref=all run=<run-url> -->` (no `session=` — the verdict run re-derives everything from the board), an @owner mention, the verdict table — one row per issue: number, title, resolved tier and the rule behind it, the judge's shadow-verdict link when one exists, gate status — with every ADR-bearing row explicitly marked **not reply-approvable** (the [ADR hard gate](../approve/SKILL.md#adr-hard-gate) is unconditional; those rows are visibility only, approved by the owner running `/approve` himself), and the reply instructions: approve in any phrasing, or "dismiss" to close without approving.

The digest's lifecycle is computed state: open = awaiting the verdict, closed = done. Nothing else stores digest progress, and a crashed run between filing and answering changes nothing — the issue rests open, the nudge pings it, the answered-or-stale branch above handles whatever the next dispatch finds.

**Not overridden — `--skip-adr`.** Sweep mode already refuses it ([`## Sweep approve`](../approve/SKILL.md#sweep-approve) step 2) and no dispatch can carry one; an unmerged-ADR candidate parks like any other gate failure, to be approved singly by the owner if the override is intended.

Everything the table does not cite — the gate checks themselves, the freshness and dependency and umbrella-integrity logic, the ADR merge gate, the per-issue tier resolution, the `phase:ready` label-reconcile mechanics, the idempotent re-run, the side-findings hands-off rule, and everything under [`## What /approve does NOT do`](../approve/SKILL.md#what-approve-does-not-do) (it dispatches no implementation, edits no issue body, and never edits `.github/approval-policy.yml`) — is `/approve`'s, verbatim.
