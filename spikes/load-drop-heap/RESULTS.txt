SPIKE load-drop-heap (issue 7414): what a load and drop of an asset bundle keeps
Base: main c34b6d44f. Host: Linux 6.17 x86_64, glibc 2.39, 32 cores, release build.
Measured 2026-10-05. Raw tables: results/sites/, results/long-series.txt,
results/series/ (every run's sample series as JSON). The dhat profiles
themselves (14 MB to 300 MB each) are not committed.

HOW TO RERUN (Linux, from the checkout root)
  cargo xtask build-wasm
  cargo build --release --target wasm32-unknown-unknown -p spike-load-drop-bundle
  CARGO_PROFILE_RELEASE_DEBUG=line-tables-only cargo build --release \
    -p aether-harness-perf --features heap-profile --bin aether-perf-load-drop
  spikes/load-drop-heap/run.sh <out-dir> [jobs]           # every cell, 3 counts, 3 modes
  python3 spikes/load-drop-heap/analyze.py <out-dir> same-ref 1000      # per-site slopes
  python3 spikes/load-drop-heap/structures.py <out-dir> same-ref 1000   # summed by structure
  python3 spikes/load-drop-heap/series.py <out-dir>/same-ref-4000.plain.series.json
One process is one cell at one count in one mode (dhat / plain / arena1 =
MALLOC_ARENA_MAX=1). The long runs and the small-ring runs were started by
hand: the reference cell's arguments plus `--samples 32`, and `--rings 16`.

THE CELLS
  The driver is crates/aether-harness-perf/src/bin/perf-load-drop: a
  SubstrateHarness with the component host, a real LoadComponent mail awaited
  to settlement (load_any), a real DropComponent mail awaited to its reply,
  and the last drop awaited to the instance's MonitorNotice before the exit
  readings. The module is spikes/load-drop-heap/bundle (release wasm,
  194,725 bytes): one instanced export whose `wire` fetches every catalogued
  asset by copy.
  ref = the shape issue 7414's figures were measured with (runite#30 churn):
        content-addressed marker, 64 assets, 1 MiB payload, 100 instances
        live, each load named churn~<n>, warm-up 132 cycles.
  same-ref              one bundle, ref shape              counts 1000/2000/4000
  same-ref-live0        ref shape, no live window
  same-ref-watch        ref shape, every drop awaited to its MonitorNotice
  same-bare             content-addressed, no assets, no live window
  same-fixture          aether_test_fixtures_bundle (debug, 10 MB, 50 exports),
                        instanced test.spike.asset_probe, counter keys
  distinct-ref          a new bundle each cycle, ref shape  counts 500/1000/2000
  distinct-ref-live0    the same, no live window
  distinct-bare         content-addressed, one 8-byte asset, no live window
  distinct-unaddressed  64 assets, 1 MiB, NOT content-addressed (each load is
                        a successor republish of one namespace)

   same-ref-live0 arena1  rss     -327.7       1075.2
   same-ref --rings 16 plain  rss  352.3       1910.8     1010 / 1156 / 678 / 2337
   same-ref --rings 16 arena1 rss 3260.4        -57.3      945 / 1085 / 790 / 1868
   (in_use = mallinfo2 in-use + mmapped bytes, block headers included;
    over 64,000 cycles it is 1,079 bytes per cycle in both modes)
   The reported 7 KiB per cycle is reproduced over cycles 1,000-4,000
   (5.7-6.6 KiB plain, 4.0-7.5 KiB arena1; 6.3 KiB over the whole span in
   both). About 1 KiB of it is live heap. The rest is not a leak:
   - every live actor is given a 491,520-byte trace ring (4,096 x 120 bytes,
     aether-actor/src/trace.rs:126) and a 73,728-byte log ring (1,024 x 72,
     aether-actor/src/log.rs:120) with capacity reserved up front
     (spawn/spawner/prepare.rs:216-217): 56.5 MB of the 70 MB live at exit
     with 100 bundles live, almost all of it never written;
   - each cycle frees one pair and allocates another; where the new pair
     lands, its first pages are touched for the first time (arena1: [heap]
     resident 25 MB at the start against 74 MB in use, 101 MB against 143 MB
     at 64,000 cycles), and under default glibc the freed pairs pile up as
     free chunks in the arenas (free bytes 38 MB -> 85 MB in the first 4,000
     cycles; malloc_trim at the end returns 48 MB);
   - it is bounded: by 16,000 cycles the resident slope is at the heap slope;
   - with 16-entry rings the resident slope equals the in-use slope from the
     first sample, and the baseline falls from 106 MB to 66 MB (plain).
   Outside the Rust heap: nothing grows. arena1, same-ref: anonymous
   executable 229,376 bytes flat, anonymous read-only 352,256 flat, memfd
   2,048,000 flat, mapping count 582 flat, anonymous read-write outside
   [heap] 233.5 / -14.3 bytes per cycle.

     the ceiling to the floor (aether-harness-substrate/src/harness.rs:661)
   - the hub / RPC path and any renderer resident
   - macOS
