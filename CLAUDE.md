# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

## Status

Pre-1.0 Rust project (edition 2024). Vision: a game engine where Claude sits in a harness as assistant/engineer/designer. A thin native **substrate** owns I/O, GPU, and audio and hosts a WASM runtime; engine **actors** — wasm components and native chassis capabilities — run on it and communicate only by **mail**. "Aether" / "the engine" is the whole system; the substrate is the native base layer. Load-bearing design is recorded as ADRs in `docs/adr/NNNN-title.md` (use `docs/adr/TEMPLATE.md` to start one) — read the cited ADR before changing a subsystem. The contributor and agent reference for using and extending aether is the **`docs/guide/`** mdbook (`docs/guide/SUMMARY.md` is the entry point; CI builds and deploys it to GitHub Pages).

## Architecture & crates

Infrastructure (non-actor) crates:

- **`aether-data`** — universal data layer (`no_std` + `alloc`). Typed-id newtypes (`MailboxId`, `KindId`), wire identity (`EngineId`, `SessionToken`, `Uuid`), schema vocabulary (`SchemaType`, `KindShape`, `KindLabels`), the `Kind` / `Schema` traits, encode/decode helpers, and the native descriptor + transform inventories. Everything that describes typed bytes depends on it. Its proc macros (`#[kind(name = …)]`, `#[derive(Kind, Schema)]`, `#[transform]`) live in `aether-data-derive`.
- **`aether-codec`** — schema-driven JSON ↔ wire bytes over `SchemaType` (`encode_schema` / `decode_schema`) plus length-prefix stream framing (`frame::*`, ADR-0072) whose body is `aether_data::wire`-encoded (ADR-0118). The workspace owns its wire format; postcard was removed and no crate depends on it.
- **`aether-kinds`** — the substrate kind vocabulary: `Tick`, `Key`, `WindowSize`, `DrawTriangle`, and the `aether.{audio,fs,render,window,input,component,camera,log,handle}.*` families.
- **`aether-math`** — `Vec2/3/4`, `Mat4`, `Quat`, `Aabb`, `Rect2` (column-major, YXZ Euler, right-handed Y-up, `f32`, `no_std`). Reach for it before hand-rolling `cross` / `dot` / `normalize` / aabb checks; add missing domain-agnostic primitives here, not locally. `[f32; 3]` survives at wire boundaries via `Vec3::from_array` / `to_array`.

Runtime + chassis (ADR-0073): the shared runtime is **`aether-substrate`**; each native capability owns its own thin crate — `aether-render`, `aether-audio`, `aether-fs`, `aether-http`, `aether-component`, `aether-lifecycle`, `aether-tcp`, `aether-rpc`, `aether-fleet`, and the rest of the `aether-<cap>` set. A cap's normative directory/identity/runtime/test shape is documented in `docs/guide/capability-anatomy.md` (ADR-0121/ADR-0122); a downstream crate depends only on the caps it uses, never on an aggregate. Each chassis lives in its own crate over the shared **`aether-chassis`** composition layer (boot fragments, fleet-wide config registry, CLI roots, autoload, boot-manifest and package-depot formats): **`aether-chassis-desktop`**, **`aether-chassis-headless`**, **`aether-chassis-hub`**, and **`aether-chassis-harness`**, plus **`aether-harness-perf`** for the perf tooling. The shippable package depot is produced by `cargo xtask package`.

The guest/actor SDK is **`aether-actor`** — the `Actor` / `WasmActor` traits, `Mailbox<K>`, `WasmCtx`, the `#[actor]` macro, and `export!` (proc macros in `aether-actor-derive`). See [Writing components](#writing-components).

## Workflow

- **Exploration and design discussion** happens in chat with the user. No artifact required.
- **Planned work** lives in GitHub Issues. `/scope` writes the managed Plan sections, declared surface, and exact size/model routing lines into the issue body. `/approve` records a trusted hidden approval bound to the Plan digest and exact base commit. Labels classify issues; they do not carry workflow state or model routing.
- **Load-bearing architectural decisions** are recorded as ADRs in `docs/adr/NNNN-title.md`. Use `docs/adr/TEMPLATE.md` when starting a new one. Number sequentially. An ADR is reviewed via a PR like any other change.
- **Branches**: `type/short-slug` (e.g. `chore/ci-bootstrap`, `feat/mail-runtime`, `docs/adr-workflow`).
- **Issue worktrees** live at `./.claude/worktrees/issue-<N>` (gitignored), never as siblings of the repo. `/implement` creates or verifies the one owned worktree and branch from the approved base before editing.
- **Spikes** run on their own `spike/<name>` branch cut from `main` (`git checkout -b spike/<name> main`), with the spike crate in its own `spikes/<name>/` subdir on that branch. `main` never carries a `spikes/` tree; the spike branches are listable via `git branch -r | grep '^[[:space:]]*origin/spike/'`.
- **Commits and PR titles** follow Conventional Commits (`type(scope): subject`). Enforced in CI against PR titles. Main uses squash-merge with the PR title as the commit subject, so PR title quality matters.
- **Draft PR proof** is current-head specific: green required checks, direct inspection of the complete diff, no active native change request, resolved review threads, declared-surface containment, and required dogfood evidence. `/implement` is the reviewer and repairs its draft; its handoff is ordinary human-readable evidence, never a visible JSON/HTML machine marker. Each push invalidates earlier head-bound proof.
- **Conflicts** on a draft use `/resolve <PR>`, which merges current `main` into the owned branch, preserves both intents inside the approved surface, and proves the resulting head again without rebasing or force-pushing.
- **Landing** is separate from implementation. `/land <PR>` independently revalidates the approval, ancestry, surface, checks, review, threads, dogfood, and merge state before clearing draft and squash-merging. Claude does not push to `main`, force-push reviewed branches, or merge without explicit landing authorization.
- **PRs** should be small and focused — one concept per PR.
- **Recursion in load-bearing code**: prefer iterative implementations (explicit work-stack/queue, arena-with-indices for tree data) over recursive ones in any algorithm whose depth could exceed a few hundred frames in practice. Recursion is OK for parse/AST walks where depth is structurally bounded by a small input file. Either way, recursive code on user-controlled or geometrically-derived data must enforce a depth/budget cap that returns an error rather than overflowing the stack.
- **No section-divider banner comments**: comments that are a run of dashes/equals (`// ----------`, `// ---- label ----`) are banned in source — use a plain comment, or split into modules if visual structure is needed. ASCII diagrams that carry real content (state machines, coordinate sketches) are fine. Enforced at edit time by the Claude hook `.claude/hooks/check-no-divider-comments.sh`.
- **Naming — units and types**: spell units out in identifiers (`millis`, `nanos`, `micros`, `secs`, `bytes`), never the two-letter abbreviation (`ms`, `ns`, `us`, `kb`) — two letters is the ambiguous zone (`ms` reads as milliseconds *or* movement-speed). Longer well-known abbreviations are fine. And don't encode a value's Rust type in its name (`u32` / `u64` / `usize`) — the signature already states it. E.g. `parse_u32_ms_strict` → `parse_millis_strict`.
- **Naming — dash-sibling namespaces**: a dash names a genuine adjacent sibling of an existing bare actor namespace, never a generic multi-word segment. `aether.kit.camera-controller` is the controller sibling of `aether.kit.camera`; the dash has no addressing semantics, so neither is nested under the other and the full `NAMESPACE` still determines identity before lineage determines its mailbox. `aether.kit.mesh` is the counter-case: `MeshViewer` is the bare mesh actor's implementation type, not a reason to call its namespace `aether.kit.mesh-viewer`. `aether.puppet-idle` and `aether.puppet-turntable` are genuine siblings of `aether.puppet`.
- **Code layout — chains, paragraphs, width**: when a value flows through successive calls, write the chain — `send(input.load()?.parse()?)`, never `let loaded = input.load()?; let parsed = loaded.parse()?; send(parsed)` — and never unroll into a mut local driven one call at a time when the API chains; a single-use intermediate earns its `let` only when the name documents a non-obvious value. Write code in paragraphs: one blank line between logical units, none inside a unit — the bindings that assemble a request are one paragraph, the send-and-assert that follows is the next; an unbroken blob makes the reader re-segment it on every read. Line width belongs to rustfmt (`rustfmt.toml`, `max_width = 120`): never hand-wrap or hand-count columns — write the code, run `cargo fmt`.
- **Module structure — the tree is a review surface**: the same logical-unit principle, one level up. Break a crate into submodules by concept — a directory per command / capability / lane, a file per phase or policy inside it, `mod.rs`-style directories, tests co-located with the code they exercise — so the file listing reads as a structured word cloud of the design: the names, counts, and nesting answer "what does this do and where do I look" before any file is opened, and a wrong name or a lopsided submodule stands out on sight. Packing a crate into one large file destroys that surface — the reader must reconstruct the structure by scrolling and hopping, and a file past a reviewer's working context breeds misreadings. Sibling directories are the template: a new command / capability / lane mirrors the shape of its siblings rather than inventing a new one, so growth stays consistent and one learned layout amortizes across the codebase. The template is a default, not a mandate — when something genuinely doesn't fit the sibling shape, structure it honestly rather than forcing the fit.

## Harness self-modification guardrail

Edits and force-pushes to files under `.claude/` — skill text under `.claude/skills/` especially — trip Claude Code's built-in self-modification guardrail: the classifier surfaces the action and asks for explicit sign-off rather than silently refusing, and a `force-push` of a skill branch additionally raises a `[Self-Modification]` / `Git Destructive` warning. On pipeline-authorized skill-text work (`/scope` → `/approve` → `/implement` → `/land`) this friction is expected and benign — the guardrail is working as designed, and the pipeline's own direction is the authorization the prompt is asking for, so the agent confirms and proceeds rather than treating the warning as a block. The classifier is harness-level and is not reconfigured here; any change to a guardrail config (`.claude/hooks/*`, classifier) needs explicit user sign-off.

## Commands

- Build: `cargo build` (release: `cargo build --release`)
- Run: `cargo run -p <crate>` — workspace root has no default binary. Each chassis binary lives in its crate: `cargo run -p aether-chassis-hub --bin aether-hub`, `-p aether-chassis-desktop --bin aether-desktop` (desktop), or `-p aether-chassis-headless --bin aether-headless`.
- Test: `cargo test` (single test: `cargo test <name>`; single-threaded with output: `cargo test -- --nocapture --test-threads=1`)
- Lint: `cargo clippy --all-targets -- -D warnings`
- Format: `cargo fmt` (check-only: `cargo fmt -- --check`)
- Type/borrow check only: `cargo check`

## MCP harness

Claude drives a running engine through MCP — the concrete form of the "Claude-in-harness" vision. The harness is the out-of-process **`aether-mcp`** crate: an RPC client that dials the hub's `RpcServerCapability` and relays each tool call as a wire `Call`. The whole stack is fronted by a long-lived **tunnel** (`aether-tunnel`, ADR-0089) so Claude can restart the volatile backends without losing its MCP connection. Three processes, one nested under the other:

```
:8890  aether-tunnel  — stable MCP front; reverse-proxies /mcp, supervises the two below
:8891  aether-mcp     — forked by the tunnel; dials + re-dials the hub
:8901  aether-hub — forked by the tunnel; the RPC server the fleet talks to
```

The tunnel binds `:8890` (the port `.mcp.json` targets) and forks `aether-mcp` (`AETHER_MCP_PORT=8891`) and the hub (`AETHER_RPC_PORT=8901`, reached via `AETHER_HUB_RPC_ADDR`) itself. Bring the stack up by running `scripts/ensure-tunnel.sh` yourself when you need the MCP harness — it is idempotent (a no-op if a **healthy** tunnel is already bound, otherwise launches one detached). Health means both supervised children are alive per `/admin/status`, not merely that `:8890` answers — a tunnel whose `hub` / `aether-mcp` children died is torn down and replaced rather than reported as up (issue 4039). It is *not* auto-started on session start: a cold `cargo` build of the tunnel can take long enough to look like a frozen session, so the launch is left to the point of use. If the `mcp__aether-hub__*` tools are missing after a mid-session tunnel start, run `/mcp` to reconnect them. A cold run pre-builds the whole fork chain, desktop included, and announces which binaries are missing before it starts so a multi-minute silent compile is not mistaken for a hang; `AETHER_TUNNEL_SKIP_DESKTOP=1` drops the desktop chassis (the wgpu / winit build that dominates that time) and leaves `spawn_substrate` resolving `aether-headless` only. Env overrides: `AETHER_TUNNEL_PORT` (default 8890), `AETHER_MCP_PORT` (default 8891), `AETHER_RPC_PORT` / `AETHER_HUB_RPC_PORT` (hub, default 8901). Get a substrate with `spawn_substrate`; the hub forks it, assigns its RPC port, and tracks the fleet via its `aether.fleet` cap.

To restart the hub after a rebuild **without dropping the MCP session**, hit the tunnel's out-of-band admin endpoint from a shell — `curl -fsS -X POST http://127.0.0.1:8890/admin/restart-hub`. The tunnel SIGTERMs + re-forks the hub child; `aether-mcp` (and Claude's MCP session) stay up and re-dial the fresh hub on the next tool call. `GET http://127.0.0.1:8890/admin/status` reports child liveness + the resolved ports. Restarting `aether-mcp` itself is rare and *does* invalidate the MCP session (Claude re-initialises) — prefer `restart-hub`.

Every engine-taking tool resolves its engine the same way: pass `engine_id` explicitly, or omit it to target the sole supervised engine — with zero or several engines an omitted id is an error naming the situation, never a guess. Those tools echo the resolved `engine_id` in their reply, so an auto-resolved answer says which engine produced it.

Tools (`mcp__aether-hub__*`):

- `list_engines(show?)` — an object `{engines, recently_died}`. `show` filters which lists come back so a routine liveness check doesn't pay for the whole fleet history: `"alive"` returns only `{engines}`, `"dead"` only `{recently_died}`, `"all"` (the default) both; the unasked list is absent from the JSON rather than present-and-empty, and any other value is a tool error. `engines` is every engine the hub supervises: `{engine_id, rpc_port, last_heartbeat_age_millis}`. The hub heartbeats each engine (`AETHER_HUB_HEARTBEAT_INTERVAL_SECS` / `_MISS_LIMIT`, default 5 s × 3) and evicts a dead/wedged one from this list once it crosses the miss limit, so a listed engine is live (ADR-0090 / issue 1339); `last_heartbeat_age_millis` shows staleness short of eviction. `recently_died` is a bounded sidecar of the last few engines that left and *why* — each `{engine_id, rpc_port, reason, detail, died_age_millis}` with `reason` one of `"terminated"` (a deliberate `terminate_substrate`), `"crashed"` (the substrate closed its connection), `"evicted"` (a missed-heartbeat eviction), or `"spawn_failed"` (a `spawn_substrate` that never connected — the substrate failed to come up, so it was never registered alive; the matching spawn error carries the same `engine_id`) — so an observer can tell a clean shutdown from a failure without grepping host logs (issue 1906, issue 2423).
- `spawn_substrate(selector?, chassis?, caps?, target?, args?, components?, mails?)` — fork+exec a substrate resolved from the hub's content-addressed binary store (ADR-0115); `selector` is a content hash, `name@version`, or `name` (`upload_binary` first if it isn't stored), and the assigned RPC port reaches the child as `--rpc-port` argv (ADR-0162; the child's environment is built from an allowlist at fork, so no `AETHER_*` key is inherited). Omit `selector` for `default` — the headless chassis — or attribute-query instead with `chassis` (`"headless"` / `"desktop"` / `"hub"`), `caps` (linked-cap superset), and `target` (build triple). Pass `components` (each `{selector, name?, config?, config_path?, export?, replicas?}`, resolved against the hub's component registry, ADR-0116 — `upload_component` first) to preload components at spawn time — `config` is inline JSON and `config_path` a JSON file path, aether-mcp schema-encodes either to the component's `Config` kind and stages a boot manifest the hub addresses to the child as `--boot-manifest` argv, and the spawned substrate loads the listed wasm itself, so no follow-up `load_component` calls are needed. Set `replicas: N` on an entry (issue 2626) to fan it out into N instances at boot from one spec, one shared config — replica 0 named for the bare `base` and each later one `{base}-{index}` (`base` = `name` > `export` > entry actor namespace), so a co-hosted peer's bare-type `ctx.actor::<R>()` reaches replica 0 and `replicas: 1` loads exactly what an omitted field loads — and the boot-readiness wait gates on every instance; pairs with `#[router(shared)]` (ADR-0136) to scale an HTTP handler to N instances with no hand-named entries. `replicas: 0` is a tool error, not a silent no-op. Pass `mails` (each `{address, kind_name, params?}` — a `send_mail` item without `engine_id`; issue 3580) to dispatch init mail once the engine and every boot component are ready, so world bring-up (create a camera, load a mesh, seed state) completes in the same call: each item settles like a `send_mail` item and reports per-item in the response's `mails` list, best-effort — a failed item aborts neither the spawn nor its siblings. Keep `capture_frame.mails` for frame-scoped placement at observation time, not initialization. Returns `{engine_id, rpc_port, last_heartbeat_age_millis}` (`0` — just spawned), plus `mails` statuses when a bundle was passed. A spawn that fails after the hub allocated an `engine_id` carries that id in the error (and records a matching `spawn_failed` entry in `list_engines.recently_died`), so a failed spawn is correlatable and reapable rather than an unidentified orphan (issue 2423).
- `upload_binary(staged_path, name?, pin?)` / `upload_component(staged_path, name?, pin?)` — stage a native binary or wasm component into the hub's content-addressed store (ADR-0115/ADR-0116). `staged_path` is an absolute path on the fleet host; the hub reads the bytes itself (aether-mcp never does — too large for the tool channel), sha256-hashes them, dedups against the store, and points `name` (when given) at the hash. Returns `{hash, name}` — the `selector` that `spawn_substrate` / `load_component` / `replace_component` resolve.
- `pin_artifact(hash)` / `unpin_artifact(hash)` — hub-local durable eviction protection for one stored artifact, addressed by the exact sha256 hex `upload_binary` / `upload_component` returned (names are never resolved; no `engine_id`; aether-mcp reads no files). `pin_artifact` records the explicit pin so the hash survives store eviction across a `restart-hub`; `unpin_artifact` drops only that explicit flag — a `name` pointing at the hash still protects it. The uploads take the same flag as `pin: true` to pin before their own eviction step (`pin: false`, the default, never clears an existing pin). Each returns `{hash, pinned}`.
- `list_binaries(chassis?, caps?, target?, limit?, include_history?)` / `list_components(namespace?, handled_kind?, limit?, include_history?)` — enumerate the stored artifact registries, newest first, under AND-combined filters. The default is the newest 20 name-pointed entries; `include_history:true` adds unnamed historical hashes and explicit `limit` changes the cap (`0` keeps only the count). Both return `{entries, total_matched, shown, truncated, notice}`; a binary entry's `manifest` is `{chassis, caps, git_sha, profile, target, env_key_count, argv_flag_count}`. To fetch a complete history, call with `include_history:true`, read `total_matched`, then repeat with that explicit limit. Component actor `handled_kinds` render as readable names with tagged-id fallbacks; the redundant manifest-wide union is omitted. Registry component entries are stored artifacts, not loaded instance lineage addresses.
- `terminate_substrate(engine_id?)` — the engine's proxy SIGKILLs the child and self-shuts-down. Returns `{engine_id, status}`.
- `send_mail(mails, fire_and_forget?, replies?)` — per-item settlement await by default: each item `{engine_id?, address, kind_name, params}` is schema-encoded, dispatched, and blocks until its chain settles (status `"delivered"`). Batch-level `replies` defaults to `"terminal"`, retaining the last arrival-ordered reply plus recognized decoded/kind-name errors; `"none"` keeps recognized errors only and `"all"` returns the complete reply stream. The per-item await cap is fixed at 300s (no knob); a timeout reports `"timeout"` with the replies collected so far. One item's failure doesn't abort siblings. `fire_and_forget:true` returns `"dispatched"` with empty replies regardless of projection.
- `send_mail_traced(engine_id?, mails, settlement_timeout_millis?, fire_and_forget?, format?)` — atomic batch under one shared trace root (the `aether.trace` mailbox), no window guessing (ADR-0080/0086). The settled default returns compact one-line-per-node `tree`, `node_count`, and `mails:null`; `format:"nodes"` returns the complete `mails` nodes, omits `tree`, and carries the same count. `settlement_timeout_millis` defaults to 300 000 and clamps at 600 000; `fire_and_forget:true` returns the ack only. A bad spec aborts the whole batch.
- `describe_kinds(engine_id?, families?, names?, prefix?, detail?)` — the engine's live capability + component kinds merged with the static substrate baseline. Returns `{engine_id, kinds}` — or `{engine_id, families}` under `families:true` — so an auto-resolved answer names the engine it came from. Default (no selectors) fills `kinds` with compact `[{name, shape}]` entries where `shape` is a one-line field rendering. `families:true` returns a sorted `[{family, count}]` digest and can combine with case-sensitive `prefix` to digest a subtree; it ignores `detail`. `names:[…]` selects exact kinds and can combine only with `detail:"schema"`, which returns their authoritative `[{name, schema}]`. Selection precedence is `families` > `names` > `prefix` > bare; `names` with another selector errors, and a bare `detail:"schema"` is refused so full-schema output stays bounded.
- `describe_component(engine_id?, address, full?)` — a loaded component's handler kinds + per-handler docs + `#[fallback]` presence (ADR-0033), returned as `{engine_id, address, capabilities}`. Docs default to the first rustdoc line per field; `full: true` returns complete rustdoc (issue 3006). Give `address` as the component's loaded lineage name (the `aether.component/aether.embedded:NAME` address `spawn_substrate` / `load_component` hand back; registry `list_components` does not return live lineage addresses) — a name resolves live against the substrate, so a boot-manifest-loaded component is introspectable without a prior `load_component` and survives an aether-mcp restart or an in-place `replace_component`. A tagged `mbx-` id is also accepted as a local cache fast-path.
- `describe_handlers(engine_id?)` — the native analogue of `describe_component`: a substrate's chassis caps' reply contracts (ADR-0109 §5), read from the link-time handler manifest the `#[actor]` macro populates and folded per mailbox namespace. Each handler carries its input kind (id + name) and its reply kind id + name, so you read a native cap's `In -> Out` (`aether.fs.read -> aether.fs.read_result`) before issuing the call; `reply` is `null` for a fire-and-forget handler, and a component-defined reply kind stays `null` because names resolve against the static substrate vocabulary.
- `compare_component_contracts(baseline, candidate)` — diff two loaded component revisions' typed-mail contracts. Each subject carries its own `engine_id` + `address` lineage, so baseline and candidate may live in different engines when a changed kind schema can't coexist in one registry. Requires a successful live `aether.inventory.kinds` refresh for each side, then compares handler input schemas, declared reply class/id/schema, `Config` schema, and fallback presence, returning deterministic additions / removals / before-after changes plus `compatible`. Removed handlers, changed input/reply/config contracts, and fallback loss are incompatible; new handlers and gaining a fallback are additive. Rustdoc, costs, logs, and assets don't affect the verdict.
- `describe_transforms` — native `#[transform]` functions linked at build time: `transform_id`, name, input/output kind ids (ADR-0048). Takes no arguments.
- `load_component(engine_id?, selector, name?, config?, config_path?, export?, replicas?, full?)` — resolves `selector` against the hub's component registry (ADR-0116; `upload_component` first if it isn't stored — the host wasm path lives only there), forwards `aether.component.load` to the engine's `aether.component` mailbox, awaits `LoadResult`. The component's kind vocabulary rides in the wasm's `aether.kinds` custom section (ADR-0028/0032). `config` is inline JSON and `config_path` an absolute path to a JSON file; either is schema-encoded to the component's `Config` kind shape before the bytes are forwarded (ADR-0090) — omit both for a no-config component. `export` names which actor type to instantiate from a multi-actor module by its `Actor::NAMESPACE` (ADR-0096); omit to load the module's declared default (`export!(default = A, …)`, ADR-0138/ADR-0147) — a multi-actor module without one refuses a selectorless load and names its exports. Capabilities docs default to the first rustdoc line; `full: true` returns complete rustdoc (issue 3006). `replicas: N` in `1..=256` (issue 2626) loops the load N times from one selector, one shared config, naming replica 0 for the bare `base` and each later instance `{base}-{index}` (same `name` > `export` > entry-namespace precedence), so a co-hosted peer's bare-type `ctx.actor::<R>()` reaches replica 0; the reply becomes `{capabilities, instances: [{mailbox_id, name}, …]}` (one shared capabilities block) instead of the single-load shape, and a mid-loop failure reports which replica failed and how many loaded before it (already-loaded replicas stay live). Pairs with `#[router(shared)]` (ADR-0136) to scale an HTTP handler to N instances in one call; values outside the accepted range are a tool error.
- `replace_component(engine_id?, address, selector, config?, config_path?, export?, full?)` — ADR-0022 in-place wasm swap. `address` is the live component (canonical lineage, ADR-0166 abbreviation, or a tagged `mbx-…` id), resolved through the same resolver `describe_component` / `actor_logs` / `send_mail` use; `selector` resolves the registry way `load_component` does. Awaits `ReplaceResult` and returns `{engine_id, address, capabilities}`. `config` / `config_path` / `export` thread init-config bytes and the exported actor type to the replacement's `init` the same way `load_component` does (ADR-0090 / ADR-0096). Capabilities docs default to the first rustdoc line; `full: true` for complete rustdoc (issue 3006).
- `capture_frame(engine_id?, window_id, mails?, after_mails?, checks?, similarity?, scale?, max_dimension?, include_image?, save_path?)` — synchronous PNG readback. `window_id` is **required**: desktop capture never guesses a primary, focused, or current window, so omitting it is a deserialize error rather than a fallback. Pass the tagged `mbx-…` string `aether.window.list` reports (a decimal `u64` is still accepted for a synthetic or harness-scale id) — it is a string because a real window id is an ADR-0099 lineage fold near 2^60, which a JSON number can't carry to a client that parses numbers as doubles. Inline images default to a 768-pixel long-edge ceiling without upscaling; `scale` (finite `(0, 1]`) applies first, then `max_dimension` clamps the scaled long edge. Captures with `checks` return verdict text and omit image content by default; `include_image` overrides either default. Each check entry may carry a `region` (`{min_x, min_y, max_x, max_y}`) to score the frame-clamped intersection instead of the whole frame. `save_path` writes the original full-resolution PNG bytes. `mails` dispatch before readback (state that should appear), `after_mails` after (cleanup); a bad bundle entry aborts the capture.
- `collect_failure_evidence(engine_id?, primary_error, operation?, actor_addresses?, component_addresses?, kinds?, frame?)` — a bounded, non-mutating bundle of live-engine evidence gathered around a failure you already have, preserving the caller's `primary_error`. Selectors are explicit and capped: at most 8 actor lineage names, 8 component lineage names, 16 exact kind names, plus an optional `frame` (`{window_id, scale?, max_dimension?}`). The result records the selected live / recently-dead fleet row, full schemas for the selected kinds, full component descriptions, and per actor a log tail (≤ 100 entries) plus its complete cost table; each observation is capped at 3 s and the bundle at 15 s, recording `success` / `error` / `timeout` / `budget_exhausted` per item rather than aborting. It never sends mail, replays the failed operation, runs checks, writes a host file, or changes lifecycle state.
- `actor_logs(engine_id?, address, max?, level?, since?, contains?)` — recent entries from one actor's per-actor log ring (ADR-0081). Any `address` is queryable (`"aether.audio"`, `"aether.component/aether.embedded:aether.camera"`). `max` defaults 100 / clamps 1000; `level` and the case-sensitive message substring `contains` filter server-side; `since` paginates via the prior call's `next_since`. Only in-actor `tracing::*` events flow into the rings (host events go to stderr). Filter with `AETHER_LOG_FILTER` (`EnvFilter` syntax; default `info`). Ring depth is a chassis-wide boot knob (ADR-0090 `ActorRingConfig`, argv > env > default, seeded into each actor's rings as it spawns): `AETHER_ACTOR_LOG_RING_SIZE` (per-actor log ring, default 1024) and `AETHER_ACTOR_TRACE_RING_SIZE` (per-actor + chassis-host trace-ring floor, default 4096). When full, the trace ring reclaims entries whose chains have already settled and grows geometrically from that floor to `AETHER_ACTOR_TRACE_RING_MAX_SIZE` (default 65536) only to protect chains still in flight, resuming drop-oldest at the ceiling — so a burst is absorbed rather than lapped, a quiet actor stays at the floor, and a stream of settled traces never inflates it. Bump the floor for steady high volume, the max for spikier bursts. The log ring has no such ceiling (drop-oldest is its intended semantic).
- `actor_cost(engine_id?, address, kind_id?)` — per-handler execution-cost EWMA table for one actor. Any `address` is queryable. Each row reports the handler kind (tagged `knd-…` id + resolved name), `mean_nanos` / `mad_nanos` (EWMA mean + mean-absolute-deviation of handler execution time), and `samples` (0 = declared but not yet run). Pass `kind_id` (tagged `knd-…` or decimal) to filter to one handler.

When verifying substrate behavior end-to-end, reach for the MCP harness before writing a new test binary.

## Test harnesses (ADR-0067)

**Tests must earn their place** (`docs/guide/testing.md`). Before writing a test, name the plausible bug it catches; if the only honest answer is "edits the test," do not write it. The decisive question: **what logic owned by *this crate* does the test exercise?** If the answer is "none — it restates a declaration or re-runs machinery another crate owns," it is junk however much ceremony (field-by-field asserts, a big value, a confident doc comment) surrounds it. Do not test code you do not own — std, the compiler, serde, wgpu/tokio/fontdue, any third-party crate, or anything the `Kind`/`Schema`/`Config` derives emit. The recurring junk shapes: a derived-constant mirror (`assert_eq!(NoteOn::NAME, "aether.audio.note_on")` — `NAME` *is* the `#[kind(name)]` literal, no independent truth); a derive-only roundtrip (`decode(encode(x)) == x` over plain `#[derive]`s — symmetric, so it only fails if the macro is broken, tested elsewhere); a derive-emitted registration check (a kind appears in `descriptors::all()` because `#[derive(Kind)]` emits the `inventory::submit!`, nothing to forget); a schema-shape assertion (`matches!(Role::SCHEMA, SchemaType::Enum)` restates the `enum` keyword). A flat assertion against a fixed value is a tripwire (KEEP) only when the pinned value is **computed** — a hash, a serialized byte layout, a derived `KindId` — so it drifts when the producing logic changes; pinning a `const NAME` against its own literal is a mirror, not a tripwire. A genuine tripwire carries a `// Tripwire:` comment naming the invariant; the comment is necessary but not sufficient (a comment over a value that cannot drift is still junk).

For Rust integration tests / CI gating without a live MCP session, two in-repo harnesses cover non-overlapping test surfaces.

**SubstrateHarness** (`aether-harness-substrate`) drives the substrate in-process over a loopback channel — no hub, no wire. `SubstrateHarness::start()` (or `SubstrateHarness::builder().size(w, h).with_actor::<C>(params).build()`) boots the basics — trace dispatch, the harness cap, lifecycle, the synthetic window, the observer mailbox — and each scenario composes the caps it needs on the builder. Drive it with `harness.execute(vec![(label, op), …])` over `HarnessOp`s — `HarnessOp::advance(ticks)`, `::capture()`, `::capture_with_mails(pre, after)`, `::send_and_settle::<K>(recipient, &mail)` (waits for the whole causal chain), `::send_and_await_reply::<K>(recipient, &mail)` (waits for that correlation id and nothing else), `::poll_until(recipient, &probe, observe)` (re-probes to a wall-clock budget for an effect no chain here can settle) — and read the returned `ExecutionResult` by label (`captured(label)`, `reply::<R>(label)`, `get(label)`), alongside `harness.count_observed(kind_name)`. The worked example is the module doc of `crates/aether-harness-substrate/src/lib.rs`, which is a running doctest, so this paragraph and the API cannot drift apart silently. `send_and_settle` encodes params the same path as the MCP `send_mail` tool, so any substrate kind is sendable. Rendering and pixel readback plug in through `aether-harness-substrate-capture`'s `RenderHarnessBuilderExt::with_render` and need a wgpu adapter; CI installs `mesa-vulkan-drivers` on Linux runners and pre-builds component wasm before `cargo test`. Pre-build the component wasm with `cargo xtask build-wasm` before running a scenario suite: without it `require_wasm` fails the scenario rather than skipping it green (`AETHER_ALLOW_WASM_SKIP=1` takes the skip deliberately). Driverless dev boxes still skip the visual scenarios cleanly.

**FleetHarness** (the `aether-harness-fleet` crate) drives the real hub → RPC → forked-headless-substrate stack over raw `WireFrame::Call` frames — the same wire protocol `aether-mcp` speaks, with the async/JSON front stripped. `FleetHarness::start()` boots a hub-shaped passive chassis and connects a raw-frame `TcpStream` client; `spawn_headless()` forks a real `aether-headless` process through the engines cap (resolved through `dist/manifest.json`, so run `cargo xtask dist` first — or point `AETHER_HARNESS_FLEET_HEADLESS_BIN` at a prebuilt binary); `load(engine, stem)` loads a component wasm and returns its lineage address; `send(engine, recipient, &mail)` issues a `Call` and returns the reply envelopes. FleetHarness is headless — no GPU, no pixel readback.

**Decision rule.** Engine-internal correctness and anything visual → SubstrateHarness. The RPC/hub boundary, `Call` recipient-name resolution, and fleet lifecycle (fork+exec, component load over the wire, engine eviction) → FleetHarness. Hard line: FleetHarness is headless, so rendered-output assertions must be SubstrateHarness; externally-addressable-over-the-wire assertions must be FleetHarness.

Wasm components are discovered structurally (issue 439): a `cargo metadata` package with `crate-type = cdylib` AND a dependency on **`aether-actor`**. Both signals are structural — no filename convention. Reach for SubstrateHarness or FleetHarness for repeatable `cargo test` verification; the MCP harness for exploratory / live observation.

## Runtime & subsystems

Each subsystem's design lives in its ADR; below is the operational surface — what to mail where. Mail is fire-and-forget unless a reply kind is noted.

- **Input streams** (ADR-0021/0068) — tick / key / mouse / window-size are publish/subscribe, keyed by `KindId`; the substrate drops events until something subscribes. A component subscribes from its `wire` hook (see [Writing components](#writing-components)); the reference `aether-kit-commons` `aether.camera` export subscribes `Tick` and `WindowSize`. Subscriptions clear on drop and survive `replace_component` (the mailbox id is stable).
- **Component lifecycle** — `aether.component.{load,drop,replace}` on the `aether.component` mailbox. `replace` swaps the wasm Module in place behind a stable mailbox handle (ADR-0022 + ADR-0038), so the mailbox id and any route cache stay valid.
- **Window** (desktop only, ADR-0035) — mail `aether.window.set_mode` (`Windowed { width?, height? }` / `FullscreenBorderless` / `FullscreenExclusive { width, height, refresh_mhz }`), `aether.window.set_title`, `aether.window.focus` (no fields — un-minimize + show + raise the window to the front, e.g. so a backgrounded window can be `capture_frame`d), `aether.window.close`, or `aether.window.request_redraw`; each replies with the value actually applied. These five are **per-window** ops: they belong to one window's own mailbox, and the `aether.window` root routes them to the sole window when exactly one is live — the common case, so a root-addressed `set_title` just works. With zero or several windows the root replies the op's `Err` naming the situation instead of picking one: address the window itself — the `mbx-…` id `aether.window.list` reports for it, or its name (`aether.window://main`); `aether.window.create { spec }` opens further windows. Root-owned kinds — `list`, `create`, the `subscribe` / `unsubscribe` family — are unaffected. Native chrome (ADR-0212) adds two more per-window ops: `aether.window.set_menu { menus }` installs a real platform menu bar (muda — macOS + Windows only; Linux and headless reply `Err`) whose chosen items publish `aether.window.menu_activated { window, id }` through the same subscribe family as `aether.key`, and `aether.window.set_cursor { icon }` sets the pointer shape from a gesture-named `CursorIcon` vocabulary; `AETHER_APP_NAME` / `--app-name` (default `Aether`) names the product for the macOS application menu, the macOS process name, and the boot window title when `AETHER_WINDOW_TITLE` is unset. Boot overrides: `AETHER_WINDOW_MODE` (`windowed` | `windowed:WxH` | `fullscreen-borderless` | `exclusive:WxH@HZ`), `AETHER_WINDOW_TITLE`, `AETHER_APP_NAME`. Window ops and `capture_frame` are desktop-only; the headless chassis replies `Err` (fail-fast) rather than hanging, at the root and at a window mailbox alike.
- **Headless chassis** (ADR-0035) — ticks from a std timer (`AETHER_TICK_HZ`, default 60). Same hub client / mail scheduler / component surface as desktop; a nop `aether.render` mailbox absorbs `DrawTriangle` + `aether.view_projection` so desktop-built components don't warn-storm.
- **Rendering & camera** (ADR-0066, ADR-0074 §7) — vertex geometry is world-space; the substrate applies a 4×4 `view_proj` uniform (column-major, defaults to identity). A camera publishes `aether.view_projection { view_proj: [f32; 16] }` to the `aether.render` mailbox (latest wins). Depth test is on (`Depth32Float`, `LessEqual`): larger world-z draws on top, so floors / backdrops sit at `z = 0` and movers at `z ≥ 0.1`. Reference: `aether-kit-commons`'s `aether.kit.camera` export (selector `aether_kit_commons@aether.kit.camera`; multi-camera / multi-mode; driver kinds `aether.kit.camera.{create,destroy,set_active,set_mode,orbit.set,topdown.set}`). To move a camera with the keyboard, load `aether-kit-commons`'s `aether.kit.camera-controller` export (selector `aether_kit_commons@aether.kit.camera-controller`, `aether.kit.camera-controller.config` init-config for target camera / mode / speeds / clamps): it subscribes `Key`/`KeyRelease`/`Tick` and mails `aether.kit.camera.{orbit,topdown}.set` deltas to a peer camera (WASD pan, arrows yaw/pitch, Z/X zoom; zero mail while idle), keeping the camera itself a pure projection state machine.
- **Textured quads** (ADR-0105) — the generic image surface text / sprites / HUD compose, on the same `aether.render` mailbox. `aether.render.create_texture { width, height, pixels }` stages an RGBA8 texture and replies `create_texture_result` with a session-scoped `texture_id` (assigned like ADR-0103 instrument ids; lazily realized on the GPU at record time); `aether.render.update_texture { texture_id, x, y, width, height, pixels }` overwrites a sub-rect (fire-and-forget, atlas growth); `aether.render.destroy_texture { texture_id }` releases a registered texture (fire-and-forget; headless absorbs). `aether.render.draw_textured_quads { texture_id, space, clip, blend, quads }` draws a batch of alpha-blended quads (each `{ x, y, width, height, u0, v0, u1, v1, tint }`) in a second overlay pass after the world pass — accumulate-per-frame like `draw_triangle`. `space` is `Screen` (window-pixel rects under an ortho from the surface size) or `World { anchor, scale }` (camera-anchored labels; the anchor is transformed through `view_proj`, offsets applied in clip space so labels always face the camera). Headless absorbs `update_texture` / `destroy_texture` / `draw_textured_quads` (no-op) and replies `Err` to `create_texture`.
- **Shapes** (ADR-0213) — `aether.render.draw_shapes { space, clip, shapes }` on the same `aether.render` mailbox draws a batch of boxes (each `{ x, y, width, height, corner_radius, fill?, stroke? { width_pixels, color }, shadow? { blur_pixels, offset, color } }`) evaluated as a rounded-box signed distance field on the GPU: shadow under fill under inside-stroke, every edge anti-aliased. A radius at or above half the shorter side is a circle, a stroke with no fill is a ring, a shadow with neither is a soft halo, and `corner_radius: 0.0` with a `fill` alone is a flat rect — which is why there is no separate flat-quad verb. An optional `texture { texture_id, u0, v0, u1, v1, blend }` samples an image inside the fill's coverage (`fill` acting as its tint), so a rounded avatar or a circular icon is one shape rather than an impossible combination of two verbs. `space` is `Screen` / `World` exactly as on `draw_textured_quads`, and `aether.render.draw_screen_triangles { space, clip, triangles }` carries it too, so the overlay's three verbs are one per fragment stage (sample a texture, evaluate a distance field, rasterize caller geometry) and each takes the same `{ space, clip }`. `blend` appears only on the two verbs that composite a caller-supplied image (`draw_textured_quads`, `material.textured`). It takes the same painter position and scissor as any other overlay batch through its own pipeline — one more overlay draw, never a pass or a layer — and callers supply parameters, never WGSL. Accumulate-per-frame like `draw_triangle`; headless absorbs it.
- **Text** (ADR-0105, the `aether.text` mailbox) — a CPU-only cap that composes the textured-quad surface into glyphs. `aether.text.load_font { namespace, path }` fetches a TTF through `aether.fs`, parses it off the hot path (fontdue), registers it under a session-scoped `font_id`, and replies `load_font_result` (`Ok { font_id, name, resident_bytes }` / `Err`) — mirrors `aether.audio.load_instrument`. `aether.text.draw { font_id, text, size_pixels, color, space }` is fire-and-forget immediate mode: it lays the string out, rasterizes unseen glyphs into a shelf-packed atlas (one `update_texture` each), and sends the `draw_textured_quads` batch to `aether.render` the same tick — resend every frame like `draw_triangle`. `color` is a linear RGBA multiplier over glyph coverage. `Screen` anchors at the window's top-left; `World { anchor, scale }` centers the string on the world-space anchor, with the baseline at the anchor and glyphs above it (`Distance` scale shrinks with depth; `Pixels` holds constant screen size). The atlas is created lazily on first draw and does not evict — a full atlas drops new glyphs. Registered on desktop / headless / substrate-harness (CPU-only). Reference tutorial: `docs/guide/recipes/drawing-text.md`.
- **Mesh authoring** — load `aether-kit-commons`'s `aether.kit.mesh` export (selector `aether_kit_commons@aether.kit.mesh`), then mail `aether.kit.mesh.load { namespace, path }` to it: it fetches the file via `aether.fs`, dispatches on extension (`.dsl` → `aether-mesh`'s parser + mesher with polygon wireframes; `.obj` → built-in fan-triangulation), atomically swaps the cached triangle list (a parse / mesh failure keeps the previous mesh and logs the error), and replays it to `aether.render` every tick. Agent loop: `aether.fs.write` the DSL text, then `aether.kit.mesh.load` the same path. DSL vocabulary + palette: ADR-0026 / ADR-0051; examples in `crates/aether-mesh/examples/` (box, lamp_post, teapot).
- **File I/O** (ADR-0041) — mail `aether.fs.{read,write,delete,list}` to the `aether.fs` mailbox. Every request and reply in the family addresses its file through one `addr` object — `{"namespace": …, "path": …}` — so a write is `{"addr": {"namespace": "save", "path": "slot.bin"}, "bytes": …}` and a read is the same `addr` alone; `list` addresses a prefix through the same `addr.path` (empty lists the namespace root). Three namespaces, addressed by short prefix (`"save"`, not `"save://"`): `save` (writable, per-user persistent), `assets` (read-only), `config` (writable). Replies echo `addr` for correlation; `FsError` is `NotFound` / `Forbidden` / `UnknownNamespace` / `AdapterError`. Env: `AETHER_SAVE_DIR`, `AETHER_ASSETS_DIR`, `AETHER_CONFIG_DIR`. Desktop + headless only. `Bytes`-typed fields (e.g. `aether.fs.write`'s `bytes`) accept either a literal byte array (`[…]`, the canonical form) or one `$`-sigil blob embed that aether-mcp resolves into bytes before the wire `Call`: `{"$file": path}` reads a file on the harness host (errors above `AETHER_MAX_FRAME_SIZE` — stage a large binary as a hub-read path instead), `{"$base64": s}` decodes, `{"$text": s}` UTF-8-encodes. The wire codec stays strict and canonical (`Bytes` is a byte array, one representation); the embeds live only in the MCP front. A reply `Bytes` field (e.g. `aether.fs.read_result.bytes`) renders one of three ways by size: at or under `AETHER_MCP_REPLY_INLINE_MAX_BYTES` (default 16 KiB) it inlines — a plain string when the content is valid UTF-8, else `{"base64": …}`; over that threshold (regardless of UTF-8 validity) aether-mcp spills the bytes to a harness-host temp file (`aether-reply-<uuid>.bin` under the system temp dir) and renders the leaf as `{"file": "<absolute host path>"}`. This surgical leaf spill runs before the 32 KiB whole-response backstop, so the surrounding status/root/reply structure can remain inline. A spill IO error falls back to the inline base64 form (the projector never errors or drops reply data). The leaf threshold is independent of the RPC frame cap (`AETHER_MAX_FRAME_SIZE`): an over-frame reply is rejected at inbound frame decode before projection.

Every text-returning MCP tool also has a whole-response backstop: when its serialized JSON exceeds `AETHER_MCP_RESPONSE_INLINE_MAX_BYTES` (default 32 KiB), aether-mcp writes the complete response to a harness-host temp file and returns the named object `{"file": "<absolute host path>", "bytes": N, "summary": …}` instead. The structural summary reports the top-level kind and count plus a byte-bounded sample or key list, so even a huge nested value cannot re-expand the tool result. A `warn` log records the tool name, byte count, and staged path. A spill IO error logs loudly and returns the original response inline so data is never dropped. This outer guard composes with the per-`Bytes`-leaf spill above; `capture_frame` image content remains outside it but applies its own bounded-image projection (default 768-pixel long edge) and checks-driven verdict-only default.
- **Audio** (desktop only, ADR-0039 / ADR-0103 / ADR-0127) — fire-and-forget `aether.audio.{note_on,note_off,set_master_gain,set_sender_gain}` to the `aether.audio` mailbox. Built-in instruments; mixing / effects are user-space. Per-note stereo placement + per-sender level (ADR-0127): `note_on` carries a bipolar `pan: i8` (`0` center, `-128` hard left, `127` hard right, constant-power law) that positions the voice in the stereo image (`ScheduledNote::On` carries the same `pan`); `aether.audio.set_sender_gain { gain: f32 }` sets a live linear trim (clamped `0.0..=4.0`, boost allowed) keyed by the envelope sender that ducks all of that sender's sounding voices, replying `set_sender_gain_result` (`Ok { applied_gain }` / `Err`). Track playback (ADR-0103): `aether.audio.play_track { namespace, path, gain, looping }` fetches a WAV asset through `aether.fs`, decodes + resamples it off the realtime path, and plays it in its own mixer lane (never counted against the voice pool) — replies `play_track_result` (`Ok` / `Err`); `aether.audio.stop_track { namespace, path }` fades it out (fire-and-forget). Sampled instrument banks (ADR-0103): `aether.audio.load_instrument { namespace, path }` points at an `.sfz` file (a small SFZ subset — region / key range / velocity range / root key), fetches the `.sfz` plus every WAV it references through `aether.fs`, decodes + resamples them off the realtime path, appends the assembled bank to the registry past the built-in ids, and replies `load_instrument_result` (`Ok { instrument_id, name, resident_bytes }` / `Err`); a subsequent `note_on` with that `instrument_id` plays the sampled instrument (region by pitch + velocity, repitched from the root key). Loaded ids are session-scoped. Env: `AETHER_AUDIO_DISABLE`, `AETHER_AUDIO_SAMPLE_RATE`.
- **Clipboard** — mail `aether.clipboard.get_text` or `aether.clipboard.set_text { text }` to the `aether.clipboard` mailbox; each returns a typed `get_text_result` / `set_text_result`. Desktop uses the real OS text clipboard. SubstrateHarness defaults to deterministic in-memory storage and can select unavailable mode. Headless and unavailable SubstrateHarness mode reply `Err` immediately instead of hanging.
**Addressing convention.** In a mail bundle, `address` names the *mailbox*; `kind_name` names the *payload shape*. They often share a leading prefix but route independently — send `aether.audio.note_on` (kind) to `aether.audio` (mailbox), `aether.draw_triangle` to `aether.render`, or `aether.kit.camera.destroy` to `aether.component/aether.embedded:cam`. Chassis-owned mailboxes live under `aether.<name>`: `aether.render`, `aether.audio`, `aether.clipboard`, `aether.fs`, `aether.http`, `aether.window`, `aether.component`. There is no `aether.input` mailbox — key / mouse / window-size subscription is on `aether.window` and tick subscription on `aether.lifecycle`. A loaded wasm component registers at `aether.component/aether.embedded:NAME` (the `/`-rendered lineage, ADR-0099) — `LoadResult.name` returns the full address; send subsequent peer/runtime mail to that string. Bare names (`"camera"`, `"player"`) are not registered and warn-drop.

## Writing components

A component is an `Actor` whose receive side is declared with the **`#[actor]`** attribute macro on one `impl WasmActor for C` block (ADR-0033 / ADR-0074):

```rust
#[actor]
impl WasmActor for CameraComponent {
    const NAMESPACE: &'static str = "aether.kit.camera";   // default load name

    fn init<C: Resolver>(ctx: &mut C) -> Result<Self, ActorInitError> { /* build state */ }

    fn wire(&mut self, ctx: &mut WireCtx<'_, '_>) {          // post-init, mail allowed; asset load window
        ctx.actor::<LifecycleCapability>().subscribe::<Tick>(); // subscribe the calling actor
    }

    #[handler::single]
    fn on_tick(&mut self, ctx: &mut WasmCtx<'_>, _t: Tick) {
        ctx.actor::<RenderCapability>().send(&ViewProjection { view_proj });
    }
}
aether_actor::export!(CameraComponent);                    // required; emits wasm32-only FFI shims
```

One module can carry several actors: `export!(A, B, C)` (ADR-0096) exports each type and designates **no** default — a bare load of that module with no `export` selector is an error naming the available exports (ADR-0138). A module that wants one names it: `export!(default = A, B, C)` makes `A` the type `load_component` instantiates when no `export` is named (ADR-0147 renamed the slot from `entry`). A `boot = B` slot ahead of it (ADR-0147) instantiates `B` once per engine and module on every load, whatever selector the caller named; it is unconditional and never selectable.

- **Handlers**: each `#[handler::<class>] fn on_x(&mut self, ctx: &mut WasmCtx<'_>, mail: K)` — the class is explicit (`single`, `manual`, or `multi`; ADR-0134) — infers the kind from its third parameter — no typelist, no `is::<K>()`. An optional `#[fallback] fn(&mut self, ctx, mail: Mail<'_>)` catches everything else; omit it for a strict receiver. `#[actor]` codegens the dispatch table and emits the `aether.kinds.inputs` custom section that `describe_component` surfaces.
- **Lifecycle**: `init` (its ctx is `Resolver`-only — no mail yet), `wire` (mail allowed; subscribe to input here), `unwire` (teardown; the old `on_drop` is retired). Hot reload needs no flag (ADR-0101): `on_dehydrate` / `on_rehydrate` are default-no-op methods on `WasmActor` itself, present on every component — override them to carry state across a `replace_component` swap. The dehydrate side persists state through `WasmDropCtx::save_state` / `save_state_kind` (the `Persistence` ctx trait); the rehydrate side reads it back from the `PriorState` argument.
- **Sends & addressing**: address a known sibling by type — `ctx.actor::<RenderCapability>().send(&kind)` (inherits the handler's causal chain by default, ADR-0080 §7, so a downstream reply settles back into the caller's chain) / `.send_detached(&kind)` (the rare fire-and-forget opt-out that starts a fresh chain) — or hold a `Mailbox<K>` token. The native handle also offers `.send_tracked(&kind) -> MailId` for settlement subscription. This resolves through the ADR-0099 lineage carry, so it stays correct when the target is re-parented. Hand-hashing a name into a `MailboxId` (`mailbox_id_from_name` / `_pair`) bakes in the target being a depth-1 root and duplicates its `NAMESPACE` const, so both are **disallowed-by-default** in `clippy.toml` (`disallowed-methods`): any direct call needs an `#[allow(clippy::disallowed_methods)]` + a one-line reason and is a smell outside the core id/routing API (the const id defs in `aether-data`, the runtime-name escape hatch `resolve_actor` / `send_to_named`, and wire-`Call` forwarding). `Kind::ID` and the typed resolver are compile-time consts, so there is no host round-trip for address resolution. The FFI keeps a `_p32` suffix on pointer-typed exports (`receive_p32`, `on_rehydrate_p32`) for the wasm32 / wasm64 path (ADR-0024).
- **Config**: a capability configures through the ADR-0090 derive-`Config` path — a `#[derive(aether_substrate::Config)]` struct resolved argv > env > default and handed into `init` — never a naked `std::env::var` / `var_os` read. Both are **disallowed-by-default** in `clippy.toml` (`disallowed-methods`), so a direct env read fails `cargo clippy -- -D warnings` (the CI gate); a legitimately external read (the config machinery itself, a process-level tuning knob, a `HOME` / `XDG` lookup, a build script, or test code) carries an `#[allow(clippy::disallowed_methods)]` + a one-line reason stating why it is not cap config. See `docs/guide/systems/configuration.md`.
- **Kind types**: `#[aether_data::kind(name = "…")]` — one attribute that declares the kind and emits the standard stack (`Kind`, `Schema`, `Debug`, `Clone`, `Serialize`, `Deserialize`), with `copy` / `default` / `partial_eq` / `eq` / `pod` / `no_serde` / `derive(…)` naming the departures. A kind whose derive list that vocabulary can't state exactly keeps the explicit `#[derive(aether_data::Kind, aether_data::Schema, …)]` + `#[kind(name = "…")]` form. A component and the peers that talk to it share the kind crate (ADR-0066); under the `runtime` feature the same crate emits the cdylib via `export!`.

## Local checks and CI

GitHub Actions is the full build engine. Before opening or updating an implementation PR, run `cargo fmt -- --check` and `cargo clippy --all-targets -- -D warnings`; the expensive build/test/package matrix belongs to CI unless the issue asks for local proof. Branch protection requires `CI pass` and `Lint title`. Those checks prove the tree and title, not direct review, thread resolution, dogfood, or landing authority.

The working loop opens a draft, watches the current head, and repairs deterministic failures inside the approved surface. `scripts/wave-status.sh --wait <PR>` polls the checked-in CI aggregate; a fix pushed to the same branch supersedes the old run. Once green, `/implement` performs direct review, fix-or-justify handling, thread resolution, and required dogfood locally through the checked-in skills. No hosted lifecycle wrapper is implied by a script or skill name.

Manual cross-worktree `cargo doc` / `clippy` re-checks must keep each worktree on its own `target/` — never export a shared `CARGO_TARGET_DIR` across worktrees on divergent source, because cargo's incremental cache can surface a dependency last compiled from the other worktree's source, producing phantom errors that look like regressions but are tooling artifacts.

## Duplicate-code and dependency gates

`jscpd` (the `Duplicate code` CI job) is a required merge gate via the `ci-pass` aggregator: it runs token-based clone detection over `crates/` and fails when the duplicated-line percentage exceeds the threshold. Format, threshold, and min-tokens are stated as command-line flags in `ci.yml`, not in a `.jscpd.json`, and the repository deliberately has no such file: jscpd answers a malformed config with one stderr warning and a silent fall back to built-in defaults — threshold included — so the gate went green at the moment its configuration broke, whereas a bad flag it refuses outright. Change the gate's calibration in `ci.yml`, and mirror it into `verify.dup` so the lane keeps predicting the gate. `cargo-machete` (the `Unused dependencies` job) fails on an unused dependency; a false positive — a dependency used only through a macro-emitted path or an optional feature, invisible to a source-only scan — is silenced per-crate via `[package.metadata.cargo-machete] ignored`, never by dropping the dependency. It runs `--no-ignore --skip-target-dir`, because its walk otherwise skips gitignored files: a `.gitignore` pattern matching a crate path would drop that crate from the scan and the gate would report no unused dependencies over a crate it never opened. Both gate through `ci-pass`, so branch protection requires only the `CI pass` aggregator.

RustRover's IDE inspector is **not** a merge gate: it analyzes the IDE's open project and rehosts only a subset of the checks. Reach for RustRover MCP for rename / symbol / refactor work.
